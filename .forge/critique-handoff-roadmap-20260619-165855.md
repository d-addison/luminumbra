# Consolidated Critique Report — luminumbra Next-Session Roadmap

## Bottom line up front

The handoff's headline claims — "100% in all systems," "~601 deterministic tests," "all gates green," "ready for e2e" — collapse under a single structural fact repeated by four of five critics independently: **every pinned-hash determinism gate runs creature-less, so the gates structurally cannot execute the ecology/boids/pack/physics code paths the campaign actually hardened.** "Green" therefore proves empty-roster reproducibility, not the determinism or correctness of the new systems — and the boids order-dependence bug (a8b689c) that slipped past every gate for the whole session is live proof of the failure mode. Compounding this, **coverage is entirely unmeasured** (the "95% gate" only checks that 7 subsystem name-strings exist in an array; no gcov/llvm-cov anywhere), **performance at scale is wholly unmeasured** (the new ecology tick is O(N²)/O(N² log N), the 16k-tree forest has no budget gate, and the one perf gate is a debug-only machine-pinned catastrophe-catcher that can't certify 300fps), and **the entire 285-commit / 4 GiB session has no git remote at all** — one disk failure erases everything. The pillar ordering rests on a critique artifact that does not exist in the repo, and the handoff doc misreports its own head hash — cheap proof its ledger was never reconciled against git.

### HIGH 5 — run==replay on one box ≠ cross-platform determinism, and the "no libm transcendentals" contract is already violated on the sim path
*(determinism #3)*
- **Claim:** Every gate runs one binary / one compiler / one flag set — reproducibility, not cross-platform determinism (the thing Steam multiplayer needs), and the contract guarding it is documentation, not a guardrail.
- **Argument:** "Over-the-wire" gates are two processes of the same exe on localhost. `GameSession.cpp` is force-compiled at `-O1` to dodge a gcc-15 link error — a flag asymmetry that is exactly how FMA-contraction/opt-level float drift sneaks across TUs. The stated contract ("DeterministicMath Sin/Cos/Sqrt/Atan2 only, NO libm transcendentals on the sim path") is **already violated**: `Perception.h:49` uses `std::cos` (NOT correctly-rounded; `DeterministicMath::Cos` is deliberately a minimax polynomial *because* std::cos differs across libm), guarded only by a comment claiming "spawn-time only." (`std::sqrt` at `InstinctSystem.cpp:140` / `ScentField.h:149` is likely safe — IEEE-754 sqrt is correctly-rounded — and should be flagged for review, not banned.)
- **Evidence:** `validate-engine-frontier.ps1:4382-4431`; handoff line 188 (-O1 workaround); `Perception.h:44-49` (std::cos, comment-guarded); `DeterministicMath.h:114-160` (Cos = minimax poly, proving std::cos is intentionally banned); memory `single-pc-testing-constraint`.
- **Plan revision:** (1) Downgrade the determinism claim to "single-toolchain run==replay reproducibility; cross-compiler/cross-platform determinism is UNVERIFIED — a shipping blocker for Steam multiplayer." (2) Add a **mechanical enforcement gate** (grep/clang-tidy over sim-path TUs that FAILS on `std::sin/cos/tan/exp/log/pow`, flags `std::sqrt` for review); convert `Perception.h:49` to precompute or assert it's never on the tick. (3) Add a non-goal: the -O1 `GameSession` TU and the rest of the sim must be shown FMA/contraction-equivalent (an -O0-vs-O1 sim-path hash-equality check) before any second-box determinism is claimed.
