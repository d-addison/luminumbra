## Findings

- Property subscriptions are append-only. `Property<T>::Subscribe` only pushes callbacks into `m_callbacks`, and `m_callbacks` has no remove path or token ID (`src/luminumbra_client/ui/core/UIProperty.h:48`, `src/luminumbra_client/ui/core/UIProperty.h:88`). `UIComponent` records cleanup lambdas, but all four base binding paths store TODO no-op unsubscribers (`src/luminumbra_client/ui/core/UIComponent.h:124`, `src/luminumbra_client/ui/core/UIComponent.h:125`, `src/luminumbra_client/ui/core/UIComponent.h:150`, `src/luminumbra_client/ui/core/UIComponent.h:151`, `src/luminumbra_client/ui/core/UIComponent.h:176`, `src/luminumbra_client/ui/core/UIComponent.h:189`, `src/luminumbra_client/ui/core/UIComponent.h:208`, `src/luminumbra_client/ui/core/UIComponent.h:209`). `Destroy()` calls `CleanupBindings()`, but cleanup only executes those no-op lambdas (`src/luminumbra_client/ui/core/UIComponent.cpp:21`, `src/luminumbra_client/ui/core/UIComponent.cpp:115`).
- The leak is also a use-after-destroy risk. Base bind lambdas and component-specific binds capture `this` and stay inside the property after the component lifetime unless manually contained (`src/luminumbra_client/ui/core/UIComponent.h:114`, `src/luminumbra_client/ui/components/common/Button.cpp:83`, `src/luminumbra_client/ui/components/common/Button.cpp:93`, `src/luminumbra_client/ui/components/game/WorldList.cpp:188`, `src/luminumbra_client/ui/components/game/WorldList.cpp:200`, `src/luminumbra_client/ui/components/game/WorldList.cpp:219`).
- Rml event listener lifecycle has the same shape. `UIComponent` adds listeners to Rml elements and later clears owned pointers without removing them from the element (`src/luminumbra_client/ui/core/UIComponent.cpp:31`, `src/luminumbra_client/ui/core/UIComponent.cpp:32`, `src/luminumbra_client/ui/core/UIComponent.cpp:23`). `Rml_UIManager` allocates menu listeners with `new LambdaEventListener` and stores no owner or removal token while documents are repeatedly closed and loaded (`src/luminumbra_client/ui/Rml_UIManager.cpp:258`, `src/luminumbra_client/ui/Rml_UIManager.cpp:281`, `src/luminumbra_client/ui/Rml_UIManager.cpp:285`).
- WorldList has several visible stubbed behaviors. Loading is hard-coded false (`src/luminumbra_client/ui/components/game/WorldList.cpp:367`, `src/luminumbra_client/ui/components/game/WorldList.cpp:369`); empty state only appears for filtered-out worlds, not a first-run zero-world list (`src/luminumbra_client/ui/components/game/WorldList.cpp:374`, `src/luminumbra_client/ui/components/game/WorldList.cpp:376`); favorites are exposed but no-op (`src/luminumbra_client/ui/components/game/WorldList.cpp:158`, `src/luminumbra_client/ui/components/game/WorldList.cpp:294`, `src/luminumbra_client/ui/components/game/WorldList.cpp:392`, `src/luminumbra_client/ui/components/game/WorldList.cpp:411`); recent filtering always passes (`src/luminumbra_client/ui/components/game/WorldList.cpp:166`, `src/luminumbra_client/ui/components/game/WorldList.cpp:416`); timestamps are unparsed (`src/luminumbra_client/ui/components/game/WorldList.cpp:435`); creation-date sort falls back to ID because `WorldInfo` lacks a creation date (`src/luminumbra_client/ui/components/game/WorldList.cpp:468`, `src/luminumbra_client/ui/components/game/WorldList.cpp:469`, `src/luminumbra_client/ui/core/UIStateManager.h:86`, `src/luminumbra_client/ui/core/UIStateManager.h:91`).
- WorldList action listeners likely do not attach for generated favorite/delete buttons because markup uses classes, while lookup uses IDs (`src/luminumbra_client/ui/components/game/WorldList.cpp:294`, `src/luminumbra_client/ui/components/game/WorldList.cpp:295`, `src/luminumbra_client/ui/components/game/WorldList.cpp:324`, `src/luminumbra_client/ui/components/game/WorldList.cpp:335`).
- Ship-blocking WorldList gaps are the loading/no-world state and any visible filter/action control that lies to the user: favorite toggle/filter, recent filter, delete action hookup. Cosmetic/deepening gaps are raw timestamp presentation and creation-date sort if the sort option is not exposed.
- The 95% TDD coverage gate is configured but not evidenced as enforced by the read build files. ## Must-Fix

- Implement a subscription-token pattern for `Property<T>`. `Subscribe` should return a move-only RAII token keyed by callback ID; token destruction or explicit `Unsubscribe()` removes the callback slot. `UIComponent` should store these tokens in a `SubscriptionBag`, and `Destroy()` plus the base destructor should clear the bag. Expose `LiveSubscriptionCount()` or a test-only probe so the lifecycle can be enforced without relying on heap tools.
- Convert all component property binds to tokens. Base `BindProperty`, `BindText`, `BindValue`, `BindVisibility`, `Button::BindEnabled`, `Button::BindText`, `WorldList::BindWorlds`, `WorldList::BindSelectedWorldId`, and `WorldList::BindSearchFilter` should not leave callbacks behind after component destruction.
- Add an Rml event listener token as a separate lifecycle primitive. It should remember `(element, event_name, listener*)`, call `RemoveEventListener` before deleting the listener, and be held by `UIComponent` and `Rml_UIManager` document listener bags. This fixes both repeated document navigation leaks and stale listener pointers.
- Complete or hide WorldList's visible broken commands before shipping. Minimum shippable behavior: loading state binds to `UIState().isLoadingWorld`, empty state appears when there are zero worlds, generated favorite/delete controls attach correctly, and any visible recent/favorite filter returns truthful results. If favorite or creation-date metadata is not part of the save contract yet, remove the visible controls/sort option until `WorldInfo` and persistence support them.

## Deepening Opportunities

- Add UI screenshot smoke after the lifecycle fix. Reuse the hidden Rml/GL context to render `main_menu.rml`, `world_creation.rml`, and `world_selection.rml`, then record per-document PPM plus JSON pixel metrics for nonblank, occupied tiles, and clipped text risk.
- Expand asset processor corpus cheaply: embedded buffer current case, external `.bin`, multiple nodes with transforms, missing optional UV/normal fallback, larger index component types, malformed input with deterministic failure, and one real `.glb` from `assets/` through the same `.lmesh` reader.
- Make shader gates manifest-driven. Generate or validate a `shader_manifest.json` from actual runtime program declarations and `res/shaders`, then assert that compile/link specs and `shader_health.json` cannot drift.
- Broaden worldgen snapshots by matrix, not by format: run the existing snapshot/atlas machinery across all authored presets and a small seed corpus, then validate topology, material counts, and SDF error thresholds from a single JSON.
- Make developer-loop selection explicit. Add CTest labels (`ui`, `tooling`, `render`, `worldgen`, `perf`, `slow`, `visual`) and CMake test presets for `fast`, `ui`, `tooling`, and `frontier-artifacts` so local validation does not require all binaries every time.
- Turn the configured 95% TDD ambition into an actual coverage lane. Start with first-party line coverage on fast/unit targets and report missing high-risk areas separately for GL/driver-dependent tests.

## Frontier Proposals

- Gate-first: build a headless UI interaction harness that consumes a deterministic script such as `data/ui/tests/main_menu_flow.json`, drives RmlUi clicks and form edits, renders each checkpoint, and asserts screenshots by pixel metrics rather than golden exact images. Keep the first gate tiny: main menu -> world creation -> back -> world selection -> select first world -> load callback.
- Gate-first: generate a test-artifact dashboard from existing JSON/PPM outputs. The generator should not decide pass/fail; validators keep that role. Its first gate should prove that `ui_smoke.json`, `ui_interactions.json`, `render_captures.json`, `worldgen_layers.json`, `runtime_world_visual.json`, and performance JSON can be indexed into one static `test_artifacts/index.html` with links, schemas, pass/fail, and missing-artifact warnings.
- Gate-first: add lifecycle telemetry behind tests only. A tiny `ui_lifecycle_counters.json` should report live property subscriptions, live Rml event listeners, loaded documents, and destroyed component counts after scripted navigation loops. This makes leak regressions reviewable without requiring a debugger.
