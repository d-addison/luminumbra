# Panel 3 — Characters & Gameplay Runtime (Engine Iteration 3)

Scope: skeletal mesh + animation through the extracted pass architecture and asset pipeline; taking the gameplay fixtures (planner, event bus, scalar field, Lua) from gate-only code to runtime systems; strict engine/game decoupling (generic planner/eventbus/field = engine; archetypes/needs/content = game data).

## Current State

**Asset pipeline (static only).** `tools/asset_processor.cpp` is a single-file glTF -> `.lmesh` converter: `Vertex {pos, norm, uv}` (lines 12-16), `LMeshHeader {magic, vertexCount, indexCount, boundingSphere}` (lines 18-23), multi-primitive merge (45-85), full meshoptimizer pipeline (remap, vertex cache, overdraw, fetch — lines 94-105), binary write with `LMSH` magic (136-145). No `cgltf_skin`, joints/weights, or animation parsing anywhere. Round-trip coverage exists in `test/tools/test_asset_processor_round_trip.cpp` (synthetic glTF built in-test, magic `0x48534D4C` asserted at line 19). cgltf and meshoptimizer are vendored.

**Runtime mesh loading.** `src/luminumbra_client/rendering/Mesh.h` defines GPU-side `Mesh {vao, vbo, ebo, indexCount, boundingSphere}` (15-27). `Mesh.cpp` validates magic and exact file size (`actualSize != expectedSize` fails the load, line 114) and fixes attribute layout 0=pos, 1=norm, 2=uv (140-145). One production asset exists: `data/models/trees/tree_small_02_2k.lmesh`.

**Rendering pass architecture.** `RenderPipeline` declares the six extracted passes as friends (`RenderPipeline.h:293-298`); each pass owns its GL resources while the pipeline keeps orchestration, shared chunk slots, material LUT, and stats. `GBufferPass` already runs a two-stage geometry pass: terrain chunks then instanced static meshes (`GBufferPass.cpp:114-129`). The instanced path (`init_instanced_static_mesh`, 23-33; `geometry_pass_static_meshes`, 177-224) views EnTT `TransformComponent + StaticMeshComponent`, lazily loads meshes into a cache, sphere-culls, groups by mesh path, and draws instanced with a 10,000-mat4 instance VBO bound at attribute slots 3-6 (216-219). `RenderHealthSnapshot` / `get_render_health_snapshot` (`RenderPipeline.h:248-273`) plus the `RuntimeScenarioHarness` screenshot/PPM/pixel-stats machinery (`RuntimeScenarioHarness.h:125-133, 424-451`) provide the visual-gate substrate; an emissive-material capture already exists (`main_client.cpp:1544-1560, 2150-2185`, target found by reading `data/common/materials.json` at `RuntimeScenarioHarness.cpp:1302`).

**Gameplay fixtures are gate-only.** `InstinctPlanner`, `OrderedEventBus`, and `AethericFieldDiffusion` compile into `luminumbra_common` (`sources.cmake`) but are referenced by nothing in `src/` outside their own files — only `test/ai`, `test/simulation`, `test/aetheric` gate tests and their `.ps1` wrappers consume them. There is **no fixed simulation tick**: the main loop calls `physics->update(deltaTime)` with variable frame dt (`main_client.cpp:1773`); the only 1/60 fixed step is the boot-metrics capture mode (`main_client.cpp:1441`).

**Scripting.** `LuaApiManifest` declares a 9-entry deterministic API surface (`LuaApiManifest.cpp:80-88`: core.log/version, entity.spawn/destroy, simulation.emit_event/subscribe, time.delta_seconds, world.get_block/set_block). `LuaState` is an empty shell (`LuaState.cpp:7-15`) — no `sol::` usage anywhere in `src/`. sol2 + lua are vendored, built (`vendor/CMakeLists.txt:82,86`), and linked (`src/CMakeLists.txt:42-43`), so the dependency cost is already paid.

**ECS.** `GameSession` owns the `entt::registry` (`GameSession.h:96,103`) and the SHIELD/Water/Physics systems; no AI/animation system exists. `InstinctComponents.h` has a hardcoded-field `NeedsComponent` (hunger/thirst/fatigue/safety/curiosity, lines 13-19), `ActionPlanComponent` (42-46), and an `InstinctAgent` tag (49) — currently unused by any system.

## Findings

1. **No skeletal data anywhere in the pipeline.** `tools/asset_processor.cpp:12-16` (Vertex has no joints/weights), no `cgltf_skin`/`cgltf_animation` reference in the file; `Mesh.h:9-13` matches.
2. **`.lmesh` loader hard-fails on extra bytes.** `Mesh.cpp:110-117` computes `expectedSize` from header counts and rejects any file whose size differs — the format cannot be extended in place without a version/magic bump.
3. **Instance matrices occupy attribute slots 3-6.** `GBufferPass.cpp:216-219` and `instanced_mesh.vert:7`. A skinned vertex layout adding joints/weights must avoid or replace these slots.
4. **Instanced static mesh path drops rotation and hardcodes material.** Model matrix is translate+scale only (`GBufferPass.cpp:205-207`); `instanced_mesh.vert:33` hardcodes `MaterialID = 3u` (grass). Characters need correct rotation and per-mesh material.
5. **Grovestrider fixture is compiled into engine code.** `MakeGrovestriderHungerFixture()` at `InstinctPlanner.cpp:126-143`; worse, `InstinctPlan.passed` (190-194) and `InstinctPlannerMeetsBaseline()` (248-264) hardcode game content ("mossberry_grove", "forage") into the generic planner. The gate script also string-asserts game content against engine source (`test/ai/instinct-planner-gate.ps1:43` requires "mossberry_grove" in `InstinctPlanner.cpp`), so the relocation must update the gate atomically.
6. **OrderedEventBus is runtime-ready but unhosted.** Deterministic tick/lane/sequence ordering (`SimulationEventBus.cpp:10-19`), `drain(inclusive_tick)` (61-80), checksum replay fixture (117-134). It needs a fixed-tick host loop, which does not exist (`main_client.cpp:1773` uses variable dt).
7. **AethericFieldDiffusion is already a generic conservative scalar field.** Permeability + sealed cells, conservation tolerance 1e-9 (`AethericFieldDiffusion.cpp:14`), stability cap rate <= 0.25 (cpp:15); only the name and schema string (`AethericFieldDiffusion.h:18`) carry the game concept. 5x5 fixture in `RunAethericDiffusionFixture`.
8. **Lua manifest has no implementation behind it.** `LuaState.cpp` is empty; `LuaApiManifestMeetsBaseline` (`LuaApiManifest.cpp:127-156`) checks the manifest data structure only — nothing verifies bindings exist.
9. **materials.json emission is not consumed by the renderer.** `data/common/materials.json:50-56` gives LuminCrystal `emission [0.4,0.6,0.8]`, but the material LUT is hardcoded in `RenderPipeline.cpp:1772-1804` (alpha=1 "magical" flag) and the crystal glow is hardcoded in `lighting_pass.frag:214-243` (`vec3(0.6,0.8,1.0)` pulse). The JSON is only read by the scenario harness to aim a camera (`RuntimeScenarioHarness.cpp:1302`).
10. **Geometry stage proven at compile level only.** `magical_particles.{vert,geom,frag}` exist in `res/shaders` and compile in the render smoke test shader suite (`render_smoke_test.cpp:327`), but `Shader` has no geometry-stage constructor (`Shader.h:12`) and nothing in `src/` references the program. Advanced stages work on this GL 4.5 baseline, but engine plumbing is vert+frag only.
11. **Game-flavored fixture in engine ECS header.** `EntitySnapshot.h:51-118` (`BuildEntitySnapshotFixture`) bakes `grovestrider_alpha` / `lantern_wisp` entities with `Instinct`/`AethericField` components into `luminumbra_common/ecs` — another engine/game leak to relocate alongside the planner fixture.
12. **Two incompatible need representations exist.** `InstinctComponents.h:13-19` (fixed struct fields) vs `InstinctPlanner.h:8-11` (named `InstinctNeed` list). The runtime planner must pick one; the named list is the data-driven choice.

## Skeletal Animation Design

**Data structures (engine, `src/luminumbra_common/animation/`):**
- `Skeleton`: flat joint array, parent-before-child order; per joint: `name_hash` (fnv1a32 of glTF node name), `parent_index` (i16, -1 root), `inverse_bind_matrix` (mat4), local bind TRS. Cap 256 joints (u8 joint indices in vertices).
- `AnimationClip`: per-joint channels keyed by `joint_name_hash`; each channel holds separate translation/rotation/scale keyframe tracks (time f32 + vec3/quat values, linear interpolation; step supported via flag); `duration`, declared `sample_rate`.
- `Pose`: working buffer of local TRS per joint -> resolved global matrices -> skinning palette (`global * inverse_bind`). `SamplePose(skeleton, clip, time_seconds, out_pose)` and `BlendPoses(a, b, alpha, out)` are pure free functions over plain structs — directly gate-testable with no GL.

**File formats:** keep `.lmesh` v1 byte-identical for existing assets (the loader's exact-size check at `Mesh.cpp:114` forbids in-place extension). Introduce:
- `.lmesh` v2 with new magic `LMS2` and a header gaining `version`, `flags` (bit 0 = skinned), and `skeleton_byte_count`. Skinned vertex stream appends `joints u8x4 + weights u8x4 (normalized)` per vertex; skeleton block (joint table) embedded after indices, since a skeleton is intrinsic to its model. Loader dispatches on magic: `LMSH` -> existing path unchanged.
- Sibling `.lanim` (magic `LANM`): clips are content and many-per-skeleton, so they live in separate files keyed by joint name hashes — a clip can be retargeted to any skeleton with matching names.
- `tools/asset_processor.cpp` gains skin parsing (`cgltf_skin`: joints, `inverse_bind_matrices`, `JOINTS_0`/`WEIGHTS_0` accessors) and `cgltf_animation` -> one `.lanim` per animation (`AssetProcessor.exe model.glb out.lmesh --anims out_dir/`). meshoptimizer remap must include the skinned attributes (widen the remap vertex struct when skinned).

**Sampling/blending — CPU sampling, GPU skinning.** Pose sampling and blending run on CPU on the fixed simulation tick (deterministic, platform-testable, decoupled from frame rate); the resulting palette uploads to a GL SSBO and skinning happens in the vertex shader. GPU-side sampling is rejected for iteration 3: it breaks the determinism gate and needs compute plumbing the passes don't have. CPU cost is fine at this entity count.

**Rendering — extend GBufferPass, not a new pass.** Add `geometry_pass_skinned_meshes` as a third stage inside `GBufferPass::execute` (mirroring how the instanced path reuses `g_buffer.frag` with its own vert shader, `GBufferPass.cpp:24-26`): new `res/shaders/skinned_mesh.vert` + existing `g_buffer.frag`, so skinned meshes land in the same G-Buffer and get lighting/SSAO/shadows for free. Vertex layout: 0=pos, 1=norm, 2=uv, 3=joints, 4=weights; model matrix and `material_id` as uniforms (characters are few; start non-instanced, avoiding the slot 3-6 instance-matrix collision). Palette in an SSBO binding (`mat4[256]` per draw). A separate `SkinnedMeshPass` is only warranted later if forward/transparency needs diverge. New components: `SkinnedMeshComponent {meshPath}` and `AnimationComponent {clipPath, time, speed, blend target/alpha}` in `luminumbra_common/components`; a small `AnimationSystem` advances time and produces palettes on the fixed tick; the client pass consumes palettes via registry.

**Deterministic pose-sampling gate:** fixture skeleton (4 joints: root, spine, arm, prop) + handcrafted clip built in code (no binary fixture needed), sampled at ticks 0..N at 1/60; palette serialized as JSON with 1e-4-rounded values + fnv1a checksum — same artifact pattern as `instinct-grovestrider-hunger.json`.

**Content location (game side):** rigged models under `data/models/characters/<name>/<name>.lmesh`, clips under `data/animations/<name>/*.lanim`, referenced by archetype JSON (below). Engine ships zero character content; the gate fixture is procedural.

## Gameplay Runtime Design

**Fixed tick + EventBus host.** Add `SimulationClock` (engine, `luminumbra_common/simulation/`): accumulator over real dt, `kFixedTickSeconds = 1/60` (matches the existing capture constant, `main_client.cpp:1441`), max ticks/frame clamp. `GameSession` gains `OrderedEventBus m_eventBus` and `uint64_t m_tick`, plus `TickSimulation()` that runs per fixed tick: AnimationSystem -> InstinctSystem -> field diffusion budget -> Lua tick scripts -> `m_eventBus.drain(m_tick)`. The main loop (`main_client.cpp` IN_GAME branch near 1771-1780) feeds the accumulator; physics can stay variable-dt this iteration (changing Jolt stepping is out of scope, flagged as risk).

**Planner over EnTT with data-driven content.** New engine system `InstinctSystem` (`luminumbra_common/ai/InstinctSystem.{h,cpp}`): iterates `registry.view<NeedsComponent, InstinctAgent>`, builds `InstinctPlanRequest` from a named-need list (migrate `NeedsComponent` to `std::vector<InstinctNeed>`-style storage or a fixed array + name table — resolves Finding 12), gathers `InstinctOpportunity` entries from entities tagged with a new `OpportunityComponent {action, need, satisfaction, urgency, risk, stamina_cost}` within range, calls the already-generic `PlanInstincts`, and writes the winner into `ActionPlanComponent`. Plan selection publishes `ai.intent` events on the bus. Game data: `data/common/archetypes/grovestrider.json` declares needs (initial pressures, growth rates) and the opportunity vocabulary; a loader in `luminumbra_common/ai/ArchetypeRegistry.{h,cpp}` parses it (nlohmann is already a dependency, `EntitySnapshot.h:3`).

**Relocations (engine/game hygiene):**
- `MakeGrovestriderHungerFixture` moves out of `InstinctPlanner.cpp:126-143` into `data/common/archetypes/grovestrider.json` + a test-side loader; the hardcoded pass criteria (`InstinctPlanner.cpp:190-194`) and `InstinctPlannerMeetsBaseline` (248-264) move into the gate test as expectations against the loaded data. `test/ai/instinct-planner-gate.ps1:42-49` must be rewritten in the same change (it greps engine source for "mossberry_grove").
- `AethericFieldDiffusion` renames to `ScalarFieldDiffusion` in `src/luminumbra_common/fields/` (namespace `luminumbra::fields`); schema string becomes `luminumbra.fields.scalar_diffusion.v1`. "Aetheric" survives as the game-level field name in data/config and the existing gate keeps a thin compatibility shim until `test/aetheric/aetheric-field-diffusion.ps1` is updated.
- `BuildEntitySnapshotFixture` (`EntitySnapshot.h:51-118`) moves to test code; the engine header keeps only schema/serialize/load.

**Per-chunk scalar field runtime + emissive hookup.** New `FieldSystem` (engine): one coarse `ScalarFieldDiffusion` lattice per streamed chunk (8x8x8 cells per 16-voxel chunk — the class is 2D today; extend to 3D or run stacked 2D slabs, decision in task), stored in a `ChunkID -> field` map beside the chunk streaming map; sealed cells derived from voxel solidity, permeability from material. Diffusion advances on the fixed tick under a budget (N chunks/tick, round-robin), with boundary halo exchange between neighbor chunks (conservation must hold across the exchange — extend the conservation check to the multi-chunk sum). Sources: emissive materials (LuminCrystal voxels inject energy), game events via bus (`field.impulse` topic). Lighting hookup, minimal first step: per-chunk field aggregate uploaded as a uniform/SSBO consumed by `lighting_pass.frag`, modulating the existing crystal glow term (214-243) instead of its hardcoded `glowPulse`; simultaneously make the material LUT data-driven from `data/common/materials.json` (replacing `RenderPipeline.cpp:1772-1804`) so `emission` actually flows from JSON -> LUT -> shader. Full point-light injection from field maxima is a stretch goal.

**Lua binding surface + hot reload.** Implement `LuaState` with sol2 (vendored + linked already, `src/CMakeLists.txt:42-43`): one `sol::state` owned by GameSession, bind exactly the 9 manifest entries (`LuaApiManifest.cpp:80-88`) against GameSession services — `simulation.emit_event` -> `OrderedEventBus::publish` (tick defaults to current), `simulation.subscribe` -> bus handler trampolines, `world.get_block/set_block` -> SHIELD world (set queued, applied at tick boundary for determinism), `time.delta_seconds` -> `kFixedTickSeconds`, `entity.spawn/destroy` -> registry + ArchetypeRegistry. A binding-parity check enumerates the manifest and asserts each `module.name` resolves to a callable in the live state — turning the manifest from documentation into a contract. Scripts live in `data/scripts/` (game). Hot reload: explicit `ReloadScripts()` (file mtime poll on the fixed tick in debug builds); reload tears down script-registered bus subscriptions, re-executes files, and replays a deterministic self-test function (`on_reload_check()`), so the gate can assert old-behavior -> edit -> new-behavior with stable event checksums.

## Proposed Gates

- **G1 Pose-sampling determinism** (`test/animation/pose_sampling_gate_test.cpp` + `.ps1`): procedural 4-joint skeleton + clip, sample ticks 0..120 at 1/60, serialize palettes (1e-4 rounding) + fnv1a32 checksum to `test-artifacts/animation/pose-sampling.json`; identical checksum across runs and across debug/release presets — same artifact pattern as `instinct-grovestrider-hunger.json`.
- **G2 Skinned render capture**: new runtime scenario `skinned_mesh_visual_smoke` in `RuntimeScenarioHarness` — spawn the T10 character, advance N fixed ticks, capture PPM via the existing screenshot machinery (`RuntimeScenarioHarness.h:424-451`), assert (a) `RenderHealthSnapshot` reports the skinned shader ok and no GL errors, (b) two captures at different clip times differ in the character ROI (proves deformation), (c) pixel stats show non-background coverage in the ROI.
- **G3 Planner scenario gate**: load `data/common/archetypes/grovestrider.json`, build the scenario from data (not code), run `PlanInstincts` via `InstinctSystem` against a registry with seeded need/opportunity entities, assert ranked order + checksum `fnv1a32:5bfeaba9` equivalence (recomputed against the data file), and assert `InstinctPlanner.cpp` no longer contains content strings (inverts the current `instinct-planner-gate.ps1:43` assertion).
- **G4 Field-conservation runtime gate**: headless multi-chunk `FieldSystem` run — 3x3 chunk grid, impulses + sealed regions, 600 fixed ticks under the per-tick budget; assert summed cross-chunk energy conservation error <= 1e-9 each tick, stability (max_delta monotonic decay), and run-to-run checksum equality; artifact `test-artifacts/fields/field-conservation-runtime.json`.
- **G5 Lua hot-reload gate**: load script A (emits `script.trigger` payload v1 on tick), drain and checksum; rewrite file to payload v2, `ReloadScripts()`, drain again; assert manifest binding parity still holds post-reload, old subscriptions are gone (no duplicate events), and the two checksums match expected v1/v2 values.

## Risks

1. **`.lmesh` exact-size check** (`Mesh.cpp:114`) makes any in-place format change a silent loader failure — mitigated by the new `LMS2` magic + version dispatch; v1 path must stay byte-identical (regression-covered by the existing round-trip test).
2. **Cross-preset float determinism** for pose sampling: MSVC FMA/optimization differences between debug/release could break G1 checksums. Mitigate with rounded serialization (1e-4, as the planner gate does) and scalar (non-SIMD) sampling math.
3. **Attribute slot collision**: instance matrices live at 3-6 (`GBufferPass.cpp:216-219`); skinned layout reuses 3-4 for joints/weights on a different VAO — safe per-VAO, but copy-paste between the two vertex shaders is an easy bug.
4. **Gate scripts string-assert engine source** (`instinct-planner-gate.ps1:42-49`): the grovestrider relocation breaks the gate unless the `.ps1`, gtest, and source change land atomically (one task, T5).
5. **Retrofitting a fixed tick into `main_client.cpp`** (~2500-line main with scenario branches): the accumulator must not disturb the existing visual-gate scenarios that assume per-frame updates; physics stays variable-dt this iteration, so sim-tick systems and physics can observe different times.
6. **Per-chunk field memory/CPU**: 8^3 doubles x 3 arrays ≈ 12 KB/chunk plus halo exchange; with hundreds of streamed chunks the tick budget (T6) is load-bearing, and budgeted round-robin diffusion makes per-chunk progress frame-rate dependent — checksum gates must run headless with a fixed chunk set.
7. **sol2 compile cost / warnings-as-errors**: sol2 is header-heavy and historically noisy under `/W4 /WX`; the recent commit history shows the project gates on warnings-as-errors, so wrap sol2 includes with pragma suppression early (it is currently linked but never included).
8. **Two need representations** (`InstinctComponents.h:13-19` vs `InstinctPlanner.h:8-11`) — picking the named-list form changes `NeedsComponent`'s shape; check nothing serializes it yet (EntitySnapshot fixture does, `EntitySnapshot.h:58-64`, and moves in the same iteration).
9. **materials.json -> LUT unification** (T7) changes terrain shading inputs globally; the material visual smoke gate (`FindMaterialVisualCameraTarget`, material pixel ratios) may need threshold retuning.
10. **Geometry/compute stages are compile-proven only** (`render_smoke_test.cpp:327`; `Shader.h:12` is vert+frag): the chosen CPU-sample/GPU-skin design deliberately avoids needing them, but any drift toward GPU pose sampling adds Shader-class plumbing first.
