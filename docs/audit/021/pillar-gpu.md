# Pillar audit: GPU modernization — RHI / Vulkan / DX12 / DLSS / hardware RT (Spec 021, 2026-07-02)

**Verdict.** The direction is fully decided and zero percent shipped: spec 014 decides Diligent-thin-seam + DLSS-via-Streamline + single-source-HLSL + HW-RT-from-the-MC-mesh (docs/specs/014-rhi-vulkan-dx12-migration/spec.md:9-34), but the tree contains **no GPU-vendor code at all** — no `rhi/` directory, no Diligent vendored, no `vulkan.h`/`VK_`/`nvapi`/Streamline/NGX/DLSS/D3D12/dxgi reference anywhere in `src/` or `include/`, and the only "Nsight" in source is a marker-only enum whose builder always returns `capture_started = false` (src/luminumbra_client/rendering/CaptureHooks.cpp:44-45). What HAS moved is the prerequisite seam: the spec-016 `RenderContext` pass contract is adopted by 10 of the 13 passes and is explicitly documented as "the seam spec 014's RHI backend implements BEHIND" (src/luminumbra_client/rendering/RenderContext.h:22-23), the FR-D shader-reflection substrate landed 2026-06-28 (commit 6bb83b17) with the SPIRV-Cross hand-off called out in its header (ShaderReflection.h:21-23), and the 017-A readback ring landed 2026-06-29 (ca2616d8) with a deliberately backend-agnostic API "spec 014's RHI backs ... with timeline semaphores / DX12 fences" (AsyncReadbackRing.h:19-21). The hard gate (016 seam + FR-D reflection + resource registry before the 014 pilot) is real and **not yet satisfied**: the designated pilot pass DebugViewPass is not on the seam (passes/DebugViewPass.h:52), reflection coverage is one pass out of thirteen (only passes/LightingPass.cpp:37-54), the registry is an adopt-only wrapper over raw GL names (RenderResourceRegistry.h:19-21), and the DLSS insertion point (TAAU) is an inline RenderPipeline method with no internal-render-scale plumbing (RenderPipeline.cpp:3024; res/shaders/taau_resolve.frag:2). The 014 pilot stays Wave 3 per the merged roadmap; the pillar's near-term executable work is closing those pilot-readiness gaps.

## Current state + evidence

### The decided direction (spec 014, revised by the F3 critique)

- **Diligent Engine is the decided RHI** — the only surveyed library shipping Vulkan + DX12 + **GL** backends with built-in cross-backend RT under a permissive license; the GL backend is the linchpin enabling in-process GL-vs-new-backend FLIP parity while shipping stays on GL (docs/specs/014-rhi-vulkan-dx12-migration/spec.md:9-17).
- **DLSS is decided via NVIDIA Streamline** (Diligent ships no NGX), consuming the motion vectors + depth + jitter already produced for TAAU; DLSS replaces TAAU on capable hardware, TAAU stays the universal fallback (spec.md:19-23, FR-G.1-FR-G.4 at spec.md:222-229).
- **Shaders are decided single-source HLSL**: DXC→DXIL (DX12), DXC→SPIR-V (Vulkan), SPIRV-Cross for reflection and GL emission (spec.md:24-27, FR-F.1-FR-F.5 at spec.md:207-218).
- **HW-RT is decided**: BLAS from the near-field marching-cubes mesh, TLAS over streamed chunks, an RT-GI/AO pass default-OFF behind `LUMIN_RT=1`; the SDF far-field stays analytic (spec.md:29-34, FR-H.1-FR-H.5 at spec.md:233-246). RT-GI/AO also closes the coarse-LOD-ignores-SDF cave-lighting gap (FR-H.5, spec.md:243-246).
- **The F3 revision replaced the big-bang**: Phase A is seam-only; Phase A0 is a two-pass pilot — DebugViewPass (low risk) + lighting or SSAO (high risk) — proven on **both** GL-via-Diligent and native Vulkan via in-process FLIP before mass porting (spec.md:41-56, FR-A0.1 at spec.md:139, FR-A0.2 at spec.md:144). Backend selection is a runtime flag `LUMIN_RHI=gl|vulkan|dx12` (FR-B.2, spec.md:160-162) — the flag does not exist yet anywhere in `src/` (negative grep, 2026-07-02).
- The charter re-affirms the hard gate: the 014 pilot requires the 016 seam + FR-D shader reflection + resource registry, and the plan must not schedule the pilot ahead of it (docs/specs/021-engine-framework-audit-charter/spec.md:151-153); FSR/XeSS must be named as fallback upscalers behind the same seam (charter spec.md:157-158).

### What exists in the tree today (the GL 4.5 baseline + the 014-facing seams)

- **Renderer is OpenGL 4.5**: the client requests a 4.5 context (src/luminumbra_client/main_client.cpp:2891-2892). `RenderPipeline.cpp` is 5,311 lines (measured 2026-07-02) and still owns TAAU, aerial, and god-rays inline (`execute_taau_resolve` at RenderPipeline.cpp:3024; `execute_aerial_pass`/`init_taau`/`execute_taau_resolve` declared at RenderPipeline.h:1025-1028; `m_aerial_shader`/`m_taau_shader`/`m_god_rays_shader` members at RenderPipeline.h:992-1006).
- **The 016 pass-contract seam exists and is majority-adopted.** `RenderContext` carries frame/camera/time, typed handles, and an additively-grown field union, and its header states it "is also the seam spec 014's RHI backend implements BEHIND: the handles here are backend-agnostic; today they wrap GL names, later a Diligent backend" (RenderContext.h:15-27). Converted passes taking `const RenderContext&`: GBuffer (passes/GBufferPass.cpp:207), Lighting (passes/LightingPass.cpp:121), Shadow (passes/ShadowPass.cpp:52), Skybox (passes/SkyboxPass.cpp:82), SSAO (passes/SsaoPass.cpp:117), Water (passes/WaterPass.cpp:127), Foliage (passes/FoliagePass.cpp:889), Particle (passes/ParticlePass.cpp:614), PlantProcgen (passes/PlantProcgenPass.cpp:106), FinalBlit (passes/FinalBlitPass.h:30). No pass includes `RenderPipeline.h` (grep of passes/, 2026-07-02; FinalBlitPass.h:13 documents the rule).
- **Not on the seam**: DebugViewPass — the designated 014 pilot pass — executes as `execute(const GBuffer& gbuffer, int mode)` (passes/DebugViewPass.h:52); GroundDecalPass takes a raw GL texture name (`execute(GLuint gPositionTexture, ...)`, passes/GroundDecalPass.h:38); ShieldRtFarFieldPass takes raw matrices (passes/ShieldRtFarFieldPass.h:83-85); TAAU/aerial/god-rays are inline pipeline methods (above).
- **Typed handles + registry exist but are GL-thin and adopt-only.** Handles are strongly-typed wrappers over GL names (RenderResourceHandles.h:22-26) and deliberately NOT a frame graph — "no automatic barrier insertion / transient aliasing. That can be added later if the Vulkan port (spec 014) needs it" (RenderResourceHandles.h:15-17). The registry "primarily ADOPTS externally-owned GL objects", with ownership moving off the pipeline only in "later 016 phases" (RenderResourceRegistry.h:9-17), and adopted entries are cleared/re-adopted per frame (RenderResourceRegistry.h:53-54). Spec 016 FR-B-002 (barrier/layout ownership, docs/specs/016-render-framework-frame-graph/spec.md:101) and FR-C-001 (declarative pass list, spec.md:110) are not implemented — no frame-graph/pass-list structure exists in RenderPipeline.cpp (negative grep, 2026-07-02).
- **Shader reflection (016 FR-D) — the substrate is LANDED, coverage is 1/13.** `ReflectProgramLayout` + `ValidateReflectedLayout` introspect the linked GL program and validate a pass's declared `ExpectedLayout` (ShaderReflection.h:64,100); the header explicitly says "This is the introspection substrate spec-014's single-source HLSL/SPIRV-Cross path plugs into: the same ReflectedLayout will later come from SPIRV-Cross reflection" (ShaderReflection.h:21-23). It is wired into every shader link and the hot-reload rollback (Shader.cpp:84, Shader.cpp:100, Shader.cpp:125-127) and covered by the gtest-discovered `ReflectionFixture` suite (test/rendering/shader_reflection_test.cpp:138-220; registered test/CMakeLists.txt:931). But only **LightingPass** declares an `ExpectedLayout` (passes/LightingPass.cpp:37-54, marked "Spec 016 FR-D pilot" at LightingPass.cpp:28); no other pass does (grep of src/luminumbra_client, 2026-07-02).
- **DLSS integration point (TAAU + inputs).** Motion vectors are real: `GL_RG16F` texture bound at `GL_COLOR_ATTACHMENT4` (passes/GBufferPass.cpp:152-158; field documented in GBuffer.h:19-23 — note the format/attachment binding lives in GBufferPass.cpp, GBuffer.h only documents it). Halton[2,3] per-frame sub-pixel jitter is computed for the G-buffer projection, 16-sample cycle, zeroed when TAAU is off so the default render stays byte-identical (RenderPipeline.cpp:2105-2121). The TAAU resolve shader reprojects history via the motion vectors with neighborhood clamp + unsharp (res/shaders/taau_resolve.frag:19-65) and self-describes as "temporal anti-aliasing (and the hook for upsampling)" (taau_resolve.frag:2) — i.e. **no actual upscaling exists**: there is no internal-render-scale plumbing anywhere in rendering/ (negative grep for render_scale/internal_res/upscale, 2026-07-02), and TAAU itself is flag-gated default-OFF (`m_taau_enabled = false`, RenderPipeline.h:1001; taau_resolve.frag:6-7). An exposure seam slot exists on the context but is a sentinel-0 placeholder until 015 A-T05/A-T06 populate it (RenderContext.h:150-155).
- **Capture hooks are marker-only — verified.** `CaptureBackend::Nsight` is an enum value (CaptureHooks.h:11); `BuildCaptureReadyMarker` always returns `capture_started = false` with diagnostic "`<backend> SDK trigger is not linked; emitted capture-ready marker`" (CaptureHooks.cpp:44-45). No RenderDoc/PIX/Nsight SDK is linked anywhere.
- **The software ray tracer HW-RT augments (never replaces) is shipping.** ShieldRtFarFieldPass productionizes the heightfield max-mip hierarchical-DDA raymarch as a fullscreen deferred pass writing the G-buffer + `gl_FragDepth` (passes/ShieldRtFarFieldPass.h:3-15), GPU-proven by the named ctests `ShieldRtFarFieldParityGpu` / `ShieldRtFarFieldGbufferGpu` / `ShieldRtFarFieldMaxMipGpu` (ShieldRtFarFieldPass.h:19-22; registered test/CMakeLists.txt:995,1002,1009). 014 keeps the far-field analytic (FR-H.4, spec 014 spec.md:241-242).
- **The parity tooling for the migration is offline-only today.** `tools/flip_diff.py` is a candidate-vs-golden file diff with tiered FLIP/SSIM/luma backends, self-described as "the parity harness the GL->Vulkan migration uses" (tools/flip_diff.py:2-15) — but 014 FR-C.3 requires rendering GL and Vulkan **in the same process** and diffing the framebuffers (spec 014 spec.md:172-175); that in-process harness does not exist. Run-to-run full-frame FLIP of the same tree is non-deterministic (~0.057 observed; memory "Render FLIP gate run-to-run noise"), which is exactly why the in-process same-frame diff is load-bearing.
- **Readback seam (017-A) is the first landed backend-agnostic RHI-shaped interface.** `AsyncReadbackRing` exposes submit/poll/consume with "no GL names in any signature a caller sees ... spec 014's RHI backs it with timeline semaphores / DX12 fences without callers changing" (AsyncReadbackRing.h:17-21; `src_buffer` is "the GL buffer name today (an RHI buffer handle behind 014)", AsyncReadbackRing.h:63); GL fences + persistent-mapped SSBO are confined to the .cpp. Tested by the `AsyncReadbackRing` gtest suite against a real hidden GL context (test/rendering/async_readback_ring_test.cpp:76-259; test/CMakeLists.txt:316-323,930). The render-side synchronous-readback ban gate (spec 017 FR-G-001) is live: `Test-RenderReadbackAllowlist`, mode `RenderReadbackAllowlist` (.forge/scripts/validate-engine-frontier.ps1:7012-7026,7306).
- **Vendoring reality check**: dependencies are local under `vendor/` via `add_subdirectory(vendor)` (CMakeLists.txt:130; cmake/dependencies.cmake:3-4 — "all dependencies are handled locally in the vendor directory"); the vendor listing (EnTT, glad, glfw, glm, imgui, rmlui, steamworks, ...) contains no Diligent, no Vulkan SDK, no DXC/SPIRV-Cross (directory listing, 2026-07-02). Note: 014 FR-A.1 mandates FetchContent for Diligent (spec 014 spec.md:114-116), which deviates from the tree's current local-vendor practice — a deliberate choice (the worktree/junction hazard), recorded here as a discrepancy with how every other dep is vendored.
- **Shader inventory**: 55 GLSL files under res/shaders/ (directory count, 2026-07-02), zero `.hlsl` (Glob, 2026-07-02) — the full Group-F port surface.

## Gaps / debt

1. **Zero RHI code (the whole pillar is unstarted).** No `rhi/`, no Diligent, no Vulkan/DX12/NGX/Streamline symbol in `src/` or `include/` (negative greps, 2026-07-02), no `LUMIN_RHI` flag (014 FR-B.2, spec.md:160-162). The decided plan has no first line of code and also no plan.md in its spec dir (docs/specs/014-rhi-vulkan-dx12-migration/ contains only spec.md).
2. **The 014 pilot's own pass is not pilot-ready.** DebugViewPass takes `const GBuffer&` directly (passes/DebugViewPass.h:52) — it must be on the RenderContext seam before it can be "expressed against the 016 seam, not against Diligent's API" (spec 014 FR-A.5, spec.md:131-137). GroundDecalPass (GroundDecalPass.h:38) and inline TAAU/aerial/god-rays (RenderPipeline.h:1025-1028) are the other unconverted seam surfaces; TAAU matters most because DLSS replaces it (FR-G.3, spec.md:226-227) — an inline pipeline method cannot be swapped per-backend.
3. **Reflection coverage 1/13.** Only LightingPass declares an ExpectedLayout (LightingPass.cpp:37-54). The 014 shader port isolates "shader-port defects from backend defects" by validating reflected layouts per pass (FR-F.5, spec.md:216-218); without declared layouts on the other 12 passes, there is nothing to validate SPIRV-Cross output against.
4. **Registry/handles are not Vulkan-shaped yet.** Adopt-only, per-frame-cleared name→GL-id map (RenderResourceRegistry.h:19-21,53-54); no ownership (016 FR-B-003, 016 spec.md:104), no barrier/layout tracking (016 FR-B-002, 016 spec.md:101; explicitly deferred in RenderResourceHandles.h:15-17) — but 014 FR-A.4 requires explicit layouts/barriers for deferred targets (spec 014 spec.md:129-131). The gap between "strict registry" and "what Diligent's explicit-state model consumes" is unquantified debt sitting exactly on the hard gate.
5. **No upscaling seam.** TAAU is native-res TAA, default-OFF (taau_resolve.frag:2,6-7; RenderPipeline.h:1001); no internal-render-scale exists (negative grep). DLSS quality modes render at reduced internal resolution — without a render-scale seam (allocation of scaled targets, mip-bias, UV plumbing), Streamline has nothing to plug into. Exposure input is a sentinel until 015 A-T05/T06 (RenderContext.h:150-155).
6. **Capture hooks unlinked** (CaptureHooks.cpp:44-45). Charter FR-E-003 explicitly asks for the real SDK link path (charter spec.md:154-156); a linked RenderDoc/Nsight trigger is also the practical debugging tool for the Vulkan bring-up itself.
7. **No in-process dual-backend FLIP harness** — the universal 014 done-gate (FR-C.3/FR-D.2, spec 014 spec.md:172-175,187-189) has no implementation; the offline flip_diff.py is threshold-fragile across runs (memory: ~0.057 same-tree noise).
8. **55 GLSL shaders, no HLSL, no DXC/SPIRV-Cross toolchain** (res/shaders count; vendor listing) — the entire Group-F surface plus its offline compile step (FR-F.4, spec.md:213-215) is future work.

## Risks

- **Hard-gate inversion risk.** The owner emphasis on "DLSS/RT now" (charter G-5, charter spec.md:62-63) pressures scheduling the 014 pilot before the 016 seam legs are done; the charter itself forbids it (FR-E-002, charter spec.md:151-153). Every backlog item below honors 016-before-014-pilot.
- **Diligent GL-backend fidelity risk (014 OQ-6).** The whole keep-shipping-on-GL strategy assumes Diligent's GL backend reproduces current GL output within FLIP threshold (spec 014 spec.md:348-350); if a pass can't hit threshold, the parity baseline (FR-B.3) frays. Discovered only at pilot time — which is why the pilot deliberately includes one high-risk pass (FR-A0.1, spec.md:139-143).
- **FLIP threshold fragility.** Per-run full-frame FLIP is non-deterministic (~0.057 same-tree, memory "Render FLIP gate run-to-run noise") while pass-parity verdicts want tight thresholds; without the in-process same-frame harness (gap 7) the gate would be noise-limited, risking both false passes and false blocks.
- **Seam churn under parallel work.** RenderContext's field union is growing per converted pass (RenderContext.h:58-155) while 015/016/017 render work continues on the same files; the parallel-pass-divergence hazard (charter FR-F-003, charter spec.md:169-171) applies to every item touching RenderContext/registry — serialize shared-seam edits.
- **Determinism exposure is minimal by design but non-zero at the edges.** 014 is render-parity-only ("the backend NEVER feeds into world_hash", spec 014 spec.md:36-39), and the ban gates (`RenderReadbackAllowlist` validate-engine-frontier.ps1:7306; sim-side `Test-ReadbackDiscipline` :6983) guard the readback edges. The residual risk is build-system/vendor churn (Diligent vendoring touching shared CMake) breaking the debug/release smoke — mitigated by `--smoke == 6f008a9f637c40b7` after every wave (charter NG-3, charter spec.md:73-74).
- **RTX-target-only validation.** DLSS/HW-RT acceptance needs the RTX 5070 Ti; several existing GPU gates are already deliberately out of `-Mode All` for this reason (e.g. validate-engine-frontier.ps1:6449-6451). DLSS/RT items must carry hardware-gated proving signals, and CI-only environments can never prove them — plan for owner-machine verification passes.

## Opportunities

- **The pilot-readiness work is cheap and pays now.** Converting DebugViewPass + declaring ExpectedLayouts is small, pixel-neutral, immediately gate-provable work (flip_diff A/B + WorldVisualSweep) that burns down the hard gate before any Diligent code exists — Wave-2-compatible while Wave-3 waits.
- **HW-RT closes a known fidelity gap for free.** RT-GI/AO from the MC-mesh BLAS fixes the coarse-LOD-ignores-SDF cave-lighting blindness (014 FR-H.5, spec.md:243-246) — a substantive visual win beyond parity, already carved out of strict-FLIP validation (NFR-4, spec.md:267-269).
- **The upscaler seam generalizes.** Building the internal-render-scale seam for DLSS also admits FSR2/XeSS behind the same inputs (charter FR-E-004, charter spec.md:157-158; 014 OQ-4, spec 014 spec.md:344-345), giving non-NVIDIA hardware a real upscaler and decoupling the perf win from one vendor.
- **017-A set the pattern.** The ring proved the "backend-agnostic public API, GL confined to the .cpp" shape end-to-end with a hidden-context ctest and a static ban gate — the same recipe (interface + ctest + frontier gate) is the template for every RHI seam increment.
- **Reflection substrate → free layout validation for the HLSL port.** Because ReflectedLayout is already the validation currency (ShaderReflection.h:21-23), the SPIRV-Cross port can diff its reflected layout against the GL-introspected one per shader — a mechanical, high-signal port gate that exists as soon as coverage (gap 3) is closed.
