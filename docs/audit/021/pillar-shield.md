# Pillar audit: SHIELD world engine — worldgen, streaming/LOD, SDF contract, Marching Cubes, persistence (Spec 021, 2026-07-02)

The SHIELD pillar is functionally deep and unusually well-oracled — a documented SDF contract, a sim-truth-only world hash with per-system sub-hash localization, order/round-trip/corruption-hardened persistence, a budgeted deterministic streaming pipeline, and (new since 2026-06-28) a per-tick availability-set trace, main-thread wait instrumentation, and a code-grounded 017-B activation-queue design. Its one first-class live defect is the world-load hang: `EnsureSurfaceReadyNear` still blocks the interactive "CONSTRUCTING WORLD GEOMETRY" load on three unbounded job waits (`src/luminumbra_common/systems/SHIELD_WorldSystem.cpp:2834`, `:2836`, `:2991`/`:2995`); the malformed-SDF guard + opt-in watchdog stopgap has landed (hash-neutral), but the root fix is gated behind the 017-B chain (018-B contract — landed — then sim-truth/mesh decoupling, then the deterministic activation queue). The queue itself is quantified as the top streaming-perf lever (moving-anchor p99 main-thread wait 239 ms, ~50% of wall) and carries HIGH hash risk, which the landed static `--avail-trace` run==replay trace comparison is purpose-built to control (report-only today — recorded as `availability_trace_match` in the artifact, deliberately not folded into `passed`, `main_server.cpp:534-539`; the 017-B design mandates verifying it per increment). Structural debt: coarse LOD (step>1) and the far-field tiles re-derive terrain from the heightmap/analytic sampler and never read the SDF (caves/runtime edits vanish at distance), and the wrong-sized-SDF OOB hazard is guarded on the load path but not on the streaming promotion path or at the persistence boundary.

## Current state + evidence

### Worldgen

- Shaped worldgen is a pure function of (seed, params) via one shared height implementation: `GetTerrainHeightAt` delegates to `ComputeShapedHeightSample` (`src/luminumbra_common/systems/SHIELD_WorldSystem.cpp:3083-3086`), whose impl (`:583-607`) applies domain warp + continentalness/erosion/peaks splines at deterministic seed offsets (`:611-640`).
- The far-LOD worker null-shaping-generator race is guarded determinism-safely (commit `fc360183`): the four shaping generators are captured into locals once and all required non-null before shaping, falling back to the unshaped sample (`SHIELD_WorldSystem.cpp:593-607`). The commit note explicitly leaves "the underlying concurrent reinit-vs-sample race in the preview path" as a follow-up.
- Hydraulic/thermal erosion is built and preset-gated: `hydro_enabled` defaults false (`src/luminumbra_common/systems/SHIELD_WorldSystem.h:197`), applied as a baked offset in the shared height path (`SHIELD_WorldSystem.cpp:722`, `:840`, `:1265`, `:1450`), loaded from terrain presets (`src/luminumbra_common/world/TerrainPresetLoader.cpp:311`), consumed by far tiles (`src/luminumbra_common/world/FarLodStore.cpp:163`), and tested (`test/CMakeLists.txt:144` — `common/HydraulicErosion_test.cpp`). KNOWN-CONTEXT confirmed; nothing to re-implement.
- Coarse generation (T-I3-1): `GenerateChunkData(chunk, step>1)` clears the SDF and generates the 17x17 heightmap only, SIMD-batched and byte-equal to the scalar sampler (`SHIELD_WorldSystem.cpp:3813-3850`).

### SDF contract + Marching Cubes

- The contract doc exists and is precise: density semantics, padded `(CHUNK_SIZE+1)^3` grid, storage layout, GPU-callback obligations, determinism requirements (`docs/shield/sdf-contract.md:7-14`, `:25-35`, `:119-148`).
- `PolygoniseTerrain` routes step>1 to `GenerateCoarseHeightfieldTerrain` (`src/luminumbra_common/world/MarchingCubes.cpp:848-850`); the unit-step path explicitly "assumes a unit step over the full (CHUNK_SIZE+1)^3 SDF lattice" (`MarchingCubes.cpp:881-892`, `kLatticeCount` at `:892`) and takes `chunk.sdf_data.data()` with **no size validation** (`:949`). A non-empty wrong-sized SDF reads out of bounds — the leading load-hang root-cause hypothesis (heap corruption clobbering job-completion state).
- The coarse heightfield mesher samples `GetTerrainHeightAtCoarse` / the cached column heightmap — never the SDF interior (`MarchingCubes.cpp:526-587`). Confirms KNOWN CONTEXT: caves (surface-capped at 18 m, `SHIELD_WorldSystem.cpp:3826-3827`) and runtime SDF edits vanish at coarse LOD.
- Doc drift: `docs/shield/sdf-contract.md:110-113` still says "All SDF producers must fill every padded-grid sample so any supported LOD step can safely read cube corners", contradicted by the landed T-I3-1 heightmap-only coarse tier (`SHIELD_WorldSystem.cpp:3821-3833`).

### Streaming / LOD / the load path

- The per-tick streaming pass is budgeted and deterministically ordered: candidates sort by ring/distance/rank/coords (`SHIELD_WorldSystem.cpp:2690-2706`), then a generation budget takes the sorted prefix (`:2717-2745`).
- `EnsureSurfaceReadyNear` (`SHIELD_WorldSystem.cpp:2822`) is the synchronous load/teleport path: drain generation jobs (`:2834`), drain meshing jobs (`:2836`), build the surface horizon as batch jobs, then `m_job_system->wait(handle)` (`:2991` watchdog lane / `:2995` plain lane). All three waits are unbounded — this is the FR-A-003 world-load hang (charter cited `:2825/:2827/:2925`; the lines have drifted to `:2834/:2836/:2991/:2995` — recorded discrepancy). The interactive client hits it at the end of "CONSTRUCTING WORLD GEOMETRY" with radius 12/4 (`src/luminumbra_client/main_client.cpp:4588`, `:4593-4598`); the headless server boots through the same API (`src/luminumbra_server/ServerWorldRunner.cpp:265`).
- Stopgaps LANDED (commit `6fefa5fd`, 2026-06-28): phase breadcrumbs (`:2827-2836`), the malformed-SDF guard — a non-empty wrong-sized full SDF is cleared and regenerated before the unit-step polygonise, hash-neutral for valid worlds (`:2917-2934`) — and the opt-in `LUMINUMBRA_JOB_WATCHDOG` observability thread that names the wedged phase + chunk neighbourhood every 30 s without changing the wait (`:2962-2996`).
- Collision inside the load path is built inline on the main thread in deterministic iteration order (`replace_chunk_collision`, `:3056-3068`), and `has_collision` IS hash-visible sim truth (`src/luminumbra_common/persistence/WorldPersistenceRoundtrip.cpp:252`, `:765`) — any async rework must preserve deterministic collision readiness.
- The streaming meshing path builds into a scratch chunk and publishes on the main thread (`SHIELD_WorldSystem.cpp:4161-4188`); crucially, the LOD0-promotion **backfill publishes sim truth from the meshing job**: `pending_sdf_data`/`pending_heightmap_data`/`pending_material_data` move into the live chunk inside `process_completed_meshing_jobs` (`:4282-4292`), and Ready is only set there (`:4308`). This is why meshing sits on the hash-critical path and why the naive "remove the barrier" breaks determinism.
- `wait_for_streaming_jobs` = generation drain + meshing drain + publish (`:4395-4398`, `:348-365`). The server blocks in it every tick (`src/luminumbra_server/ServerWorldRunner.cpp:501`; the 017 design doc and `ServerWorldRunner.h:91` still cite `:489` — drifted).

### Persistence

- The world hash is sim-truth-only: render mesh fields are stripped via `kRenderMeshHashExcludedFields` (`WorldPersistenceRoundtrip.cpp:767-775`) with the rationale documented (`:756-766`); `ComputeWorldStreamingStateHash` checksums the projection (`:808-813`). The `--smoke` oracle requires every SIM sub-hash to match run==replay while mesh is report-only (`src/luminumbra_server/main_server.cpp:494-509`).
- Round-trip + ordering hardening is extensive: order/scramble independence, byte-exact round-trips, erase/reinsert convergence (`test/common/world_streaming_hardening_test.cpp:208-353`), far-tile persistence + border-sharing + idempotent saves (`:613-775`), and a corruption corpus covering bit-flips at every payload byte, truncation at many offsets, torn magic, future schema/container versions, and legacy migration (`test/persistence/save_load_corruption_corpus_test.cpp:119-357`).
- Gap: the chunk format validates field presence/type, not SDF lattice size — `sdf_data` round-trips verbatim (`WorldPersistenceRoundtrip.cpp:279`), fixtures deliberately use 4-sample SDFs (`:356`), and the round-trip analysis only checks non-emptiness (`:936-944`). A wrong-sized save therefore reaches runtime, where only the `EnsureSurfaceReadyNear` guard catches it.
- Far-field tiles (F1 4 m / F2 8 m) are a regenerable analytic cache keyed (seed, params_hash, tier, region), riding the LMR1 region container; edited tiles downsample edited chunks' heightmaps and are authoritative (`src/luminumbra_common/world/FarLodStore.h:3-24`).

## Gaps / debt

1. **The world-load hang is stopgapped, not fixed** (FR-A-003 mandated finding). Three unbounded waits remain on the interactive load path (`SHIELD_WorldSystem.cpp:2834`, `:2836`, `:2991`/`:2995`); the watchdog observes, the SDF guard removes one plausible cause, but nothing bounds the wait or recovers. Root fix = the 017-B activation model applied to the boot path (`activation-queue-design.md:69-71`).
2. **The per-tick barrier is the moving-lag**: 239 ms p99 main-thread block, ~50% of wall under a moving anchor (`activation-queue-design.md:12-19`; barrier at `ServerWorldRunner.cpp:501`). Neither 017-B step (decoupling, queue) has started; both are HIGH hash risk with the gates now in place.
3. **Wrong-sized-SDF OOB hazard is only half-guarded.** The guard lives in `EnsureSurfaceReadyNear` build jobs only (`:2917-2934`); the streaming meshing job copies `chunk->sdf_data` into scratch and polygonises with no size check (`:4173-4188`), and `PolygoniseTerrain` itself never validates `sdf_data.size()` against `kLatticeCount` (`MarchingCubes.cpp:892`, `:949`).
4. **Persistence accepts any SDF size** (`WorldPersistenceRoundtrip.cpp:279`, fixtures at `:356`), so a malformed save reaches runtime unquarantined — the exact ingress the load-hang hypothesis names.
5. **Coarse LOD + far field ignore the SDF**: coarse chunks mesh the heightmap (`MarchingCubes.cpp:526-587`), coarse generation skips the SDF entirely (`SHIELD_WorldSystem.cpp:3831-3833`), and far tiles are analytic heightfields (`FarLodStore.h:15-20`). Caves/overhangs/runtime SDF edits vanish beyond LOD0 — a real fidelity ceiling for the SDF-far-field engine vision.
6. **018-B is declared, not enforced**: no production TU includes `ResidencyContract.h`; the hash-scope exclusion is still the hand-maintained list 018 FR-A-003 says must be "enforced, not remembered" (`ResidencyContract.h:10-19`; `WorldPersistenceRoundtrip.cpp:767-775`; `docs/specs/018-determinism-hardening/spec.md:111-116`).
7. **FR-D-002 fast/slow-job matrix axis unwired** — the adversarial job-timing determinism axis (the one that would stress the activation queue hardest) needs an engine throttle hook (`validate-determinism-matrix.ps1:17-19`).
8. **SDF contract doc drift** (`docs/shield/sdf-contract.md:110-113` vs `SHIELD_WorldSystem.cpp:3821-3833`), and stale line references accumulating in living docs (`ServerWorldRunner.h:91` cites `:489`; charter cites `:2825/:2827/:2925`).
9. **Preview reinit-vs-sample race is guarded, not synchronized** (`SHIELD_WorldSystem.cpp:593-607`; commit `fc360183` note: "worth a proper sync follow-up").

## Risks

- **Hash risk on the 017-B chain (HIGH).** Step-1 decoupling moves WHEN sim truth is published; the queue changes WHAT settles per tick. Both are world_hash-visible if wrong. Mitigation exists and must be mandatory per increment: static `--avail-trace` per-tick MATCH + debug `6f008a9f637c40b7` byte-identical + `--smoke-moving` convergence + the determinism matrix (`activation-queue-design.md:111-116`; `main_server.cpp:514-539`).
- **`has_collision` is hash-visible** (`WorldPersistenceRoundtrip.cpp:252`, `:765`): any asyncification of the inline collision build (`SHIELD_WorldSystem.cpp:3056-3068`) must preserve deterministic collision readiness per tick, not merely eventual readiness.
- **Heap-corruption class bugs masquerade as hangs.** The OOB polygonise pathway corrupts job-completion state rather than crashing (`SHIELD_WorldSystem.cpp:2917-2921`) — until the streaming path is guarded (gap 3), an intermittent unexplained wedge remains plausible even with the load-path guard in.
- **Moving-anchor availability is convergent-by-design, not per-tick-identical** (`main_server.cpp:534-539`; `validate-engine-frontier.ps1:6853-6859`). Anyone gating 017-B on per-tick moving identity will chase a false failure; anyone RELAXING the static per-tick gate will silently lose the strongest oracle. The distinction is load-bearing and must survive into the 017-B implementation gates.
- **Generation budget interaction** — step-1 decoupling makes generation jobs heavier (full SDF at promotion), which can shift the (already convergent) moving per-tick set; acceptable iff the final moving hash holds (`activation-queue-design.md:115-116`).

## Opportunities

- The activation queue directly erases the dominant moving-play hitch (p99 239 ms → target: materially lower, measured by the landed 017-D percentiles) and is the root fix for BOTH the per-tick barrier and the load hang — one deterministic availability model, three call sites (`ServerWorldRunner.cpp:501`, `SHIELD_WorldSystem.cpp:2834-2836`/`:2991`, boot-settle `ServerWorldRunner.cpp:397`).
- 017-B also unblocks RENDER's 016 FR-E SDF-readback retirement (SDF = sim truth may only go async through the deterministic activation path) — dependency spine honored, one pillar's keystone unblocks another's.
- Making coarse LOD reduce the same SDF (or composite SDF-edit deltas onto the heightfield tiles) upgrades the far field from "terrain skin" to the actual world — the engine's stated SDF-far-field destination — with low hash risk because mesh bytes are hash-excluded (`WorldPersistenceRoundtrip.cpp:767-775`).
- The `AvailabilityKey`/`IsResident` contract (`ResidencyContract.h:100-136`) is a ready-made seam for multi-anchor/multiplayer streaming determinism (avatars already stream via the multi-anchor union, `ServerWorldRunner.cpp:490-497`).
