## 1. Far-field tree impostors (Wave 3) — the headline feature

**Status: built, validated, perf-positive, DEFAULT OFF.** Opt-in: `LUMIN_TREE_IMPOSTORS=1` (env).
Matches the codebase's experimental-render pattern — shipping render is byte-identical when off.

### What it is
Distant trees (> 200 m) draw ONE camera-facing billboard sampling an octahedral atlas (the tree
pre-rendered from 144 view directions), instead of per-part branch geometry. Collapses the far-field
forest to one instanced draw + one shared atlas.

### Files
- `src/luminumbra_client/rendering/OctaImpostor.h` — GL-free hemi-octahedral view-dir↔tile mapping.
  **Shared source of truth** for the bake AND the shader (so they can't drift).
  `test/rendering/octa_impostor_test.cpp` (6 tests). Build target `octa_impostor_test`.
- `src/luminumbra_client/rendering/ImpostorBake.{h,cpp}` — bakes the tree parts into albedo+normal
  atlases. Two entry points share a render core: `BakeTreeImpostorAtlas` (writes PPM + coverage JSON,
  used by the `--bake-tree-impostor <out.ppm>` client mode) and `BakeTreeImpostorAtlasToTextures`
  (keeps 2 GL textures for runtime).
- `src/.../RenderPipeline.{h,cpp}` — bakes the atlas at init when enabled; accessors
  `tree_impostor_*()`.
- `src/.../passes/GBufferPass.{h,cpp}` — at LOD3, tree instances divert from the mesh draw to one
  instanced billboard (collected on the leaf part via the cache-precomputed `cp.impostorLeaf`).
  `lod3Distance` pulled to 200 m when impostors are on.
- `res/shaders/tree_impostor.{vert,frag}` — world-up billboard; frag hemi-octa-encodes the view dir →
  tile, samples albedo (alpha = silhouette cutout) + object-space normal, writes ALL 5 deferred
  G-buffer attachments (octa normal+matid, albedo+rough, view-pos, metallic/AO, motion).

### How to iterate the atlas (visual)
`LUMIN_TREE_IMPOSTORS` not needed — use the dedicated bake mode:
`client_app --bake-tree-impostor build/atlas.ppm --no-audio` → writes `atlas.ppm` (albedo) +
`atlas_normal.ppm` + `atlas.ppm.json` (per-tile coverage). View with ppm_to_png.

### Perf verdict (render-benchmark A/B, forest_dense, 100 frames — commit 12f73bb7)
Impostors ON wins every metric: frame_wall 5.01→4.81 ms, cpu_submit 4.71→4.39, cpu_static_prop
0.87→0.54, gpu_gbuffer 1.38→0.90. CPU deltas are clock-independent (real); GPU drop is real but
partly clock-confounded. **Modest win that SCALES with far-field tree count.**

### KEY load-bearing fact
Forest GPU cost is **OVERDRAW/fill-bound, NOT triangle-bound** (`TreeLod.h:39-44` — a 58% triangle
cut moved gbuffer ms by 0). So the `forest_perf_budget` RedAt16kTreeLoad gate (which counts TRIANGLES)
is a **poor proxy** — always validate with `--render-benchmark` real GPU ms, not the triangle gate.
The octa quad is a TIGHT single billboard (lower overdraw than the old wide 3-quad cross-billboard the
team found regressed), which is why pulling LOD3 in to 200 m is safe.

### TO FLIP DEFAULT ON (the remaining work on this feature)
1. **Live close-up visual sign-off** — run the client with `LUMIN_TREE_IMPOSTORS=1`, walk to ~200 m
   from a stand, and check the LOD2→impostor handoff for popping / billboard orientation. A static
   headless frame-scan can't judge this; it needs eyes on the screen.
2. (Optional) tune `lod3Distance` (GBufferPass `kTreeLodCfg.lod3Distance`, currently 200) + the bake
   framing (`ImpostorBake.cpp` `hr = unionR * 0.52f`) + grid size (main_client `bakeGrid.gridResolution
   = 12`) for the best transition.
3. When it looks seamless, flip the default: in `RenderPipeline.cpp` init, make the impostor bake run
   unconditionally (drop the `LUMIN_TREE_IMPOSTORS` env gate, or default it true). One-line change.
4. The `forest_perf_budget` RED gate will then flip green; re-run `--render-benchmark` to record the
   shipped win.

## 2. Water moving-frame perf (LANDED, shipping)

Commits 9a7360f2, 43e3c7bf, 8348e0e9, 07cc9f5f, 896bd45c. Steady-state moving water cost **p50 10 →
0.4 ms** (median moving-frame water cost essentially gone), byte-identical (`--smoke` stays
`b05b642e`, NO re-pin). Mechanism: reuse the mesher's already-computed heightmap for the terrain half
of water-init (byte-identical, proven by the byte-exact parity gate) + seed INLINE (the old parallel
dispatch+wait was head-of-line blocked behind the streaming queue).

**Gotcha that cost a day:** an earlier attempt read `heightmap_data` from the *parallel* water workers
— that's a DATA RACE (shared mutable state the streaming path writes), not a value mismatch; reverted.
The fix reads the heightmap on the MAIN THREAD (sequenced with the only writer). See memory
`water-heightmap-read-race.md`. The scalar `GetTerrainHeightAt` is a pure function (race-free), which
is why it's the fallback.

**Remaining (separate effort):** the worst-frame *tail* (p90 ~20 ms) is now multi-causal — SHIELD
activation bursts (~26 ms, determinism-load-bearing — only server run==replay can validate, don't
rush), render submit (~16 ms, a GPU-driven-submit rewrite), and vsync. No single dominant killer left.
Memory: `moving-lag-streaming-amortization.md`.

## Determinism rules (sacred — applies to everything)

- Procedural geometry (plants, impostors) is VISUAL-ONLY; sim is integer/fixed-point. Render-only
  changes never touch `world_hash`.
- Local `world_hash` bumps are OK during dev (no shipped game) — but keep run==replay, ≤2 ordered
  writes, and re-pin baseline literals when a sim sub-hash changes.
- Validate sim changes with `--smoke` (run==replay) BEFORE assuming determinism. SIMD-batch vs scalar
  FP can differ in the last bits; the heightmap↔sampler parity gate is now EXPECT_EQ (byte-exact).
- Single-PC constraint: host==peer can't be locally validated; the batch heightmap is already hashed
  + claimed host==peer, so reuse of it is safe by that token.
