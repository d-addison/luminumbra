- MCRA-01 -> Spec change: `multiplayer-client-render-remote-avatars.md` decomposes `NetworkClientSession` into test-visible transport, replication, prediction, usercmd, interpolation, render-lifetime, and animation seams.
- MCRA-02 -> Spec change: remote-avatar criteria add explicit `client_id -> avatar_id -> entity_id` binding and a negative self-ghost fixture for mismatched `JoinAccept.avatar_id`, snapshot `entity_id`, and prediction state.
- MCRA-03 -> Spec change: remote-avatar gates now require a structural assertion that networked runtime render entities consume only accepted `ReplicationClient` samples, not the old debug transform path.
- MCRA-04 -> Spec change: animation evidence must advance from tick-derived sampled snapshot deltas or pinned capture time instead of wall-clock frame delta.
- MCRA-05 -> Spec change: the remote-avatar red-team lane now covers real TCP/GNS framing, stale baselines, out-of-order removed ids, and AOI leave/re-enter for the same entity id.
- MCRA-06 -> Spec change: the ghost-avatar guard is a TCP and GNS leave/rejoin lane asserting remote-table absence, zero skinned draws, cleared interpolation history, and pixel absence before re-entry.
- MMCA-01 -> Spec change: multi-client accept now uses deterministic join slots for validation lanes before monotonic id allocation, while ad hoc/manual sessions may remain timing-dependent and non-hash-bearing.
- MMCA-02 -> Spec change: `JoinRequest`/`JoinAccept` layout, endianness, length caps, versioning, nonce replay, duplicate, and overflow behavior are specified before simulation admission.
- MMCA-03 -> Spec change: host ticks freeze a deterministic cutoff for queued callbacks/frames/usercmds and add a callback-order hash scenario.
- MMCA-04 -> Spec change: the runtime manager must pass a 20-live-client spread/hotspot scale lane proving it is not a shared-transport or O(N^2) broadcast implementation.
- MMCA-05 -> Spec change: slow/flooding clients have bounded per-client drain caps, queue telemetry, drop/disconnect policy, and survivor progress assertions.
- MMCA-06 -> Spec change: the disconnect lane now asserts distinct survivor endpoint ids, independent seq/ack counters, survivor bytes, and no host-loop or poll-group reset.
- MRJL-01 -> Spec change: runtime join/leave declares multi-client accept as a prerequisite for stable endpoints, queues, deterministic slots, and admission rejection.
- MRJL-02 -> Spec change: join admission now allocates avatar and anchor, builds the baseline, and only then sends `JoinAccept`.
- MRJL-03 -> Spec change: lifecycle generation is added so stale timeout/lobby/transport leave intents cannot affect a reused endpoint/table slot.
- MRJL-04 -> Spec change: hash-bearing lifecycle lanes must use scripted tick schedules and prove callback arrival order does not move spawn/despawn ticks or hashes.
- MRJL-05 -> Spec change: lifecycle artifacts now record AOI subscription counts, resident chunks by eviction cause, avatar/anchor ids, queues, and memory around leave/rejoin.
- MRJL-06 -> Spec change: churn acceptance now asserts no stale anchors or AOI subscriptions, expected resident-budget convergence, drained queues, and memory watermark.
- MSP2P-01 -> Spec change: Steam spec now names the iteration-6 MVP slice and defers hosted dedicated SDR/coordinator ticket automation as follow-up validation.
- MSP2P-02 -> Spec change: SteamID is identity metadata while deterministic simulation uses server-assigned `client_id`; duplicate, reconnect, and spectator cases are tested.
- MSP2P-03 -> Spec change: the listen-host security claim is narrowed to identity-bearing Steam P2P unless session tickets are required and validated; ticket validation is a follow-up.
- MSP2P-04 -> Spec change: lobby metadata remains discovery-only and the red-team lane rejects stale build, capacity, duplicate identity, and non-admitted lobby members before `AddClient`.

- MSP2P-07 -> Spec change: the Steam two-machine red-team lane covers stale build, over-capacity, duplicate SteamID, `LobbyChatUpdate_t`, and connection-close races.
