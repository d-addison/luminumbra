# Third-Party Library Adoption Report — Luminumbra Engine

Decision-oriented synthesis of 12 category recommendations against the verified dependency stack. Framing constraints throughout: 30 Hz integer input-lockstep determinism (`world_hash` run==replay gates), mid-flight OpenGL→Diligent RHI migration, and Windows ucrt64 GCC 15 / Ninja / FetchContent toolchain.

**Bottom line:** the stack is in strong shape — 9 of 12 categories are keep/skip/defer. Only **two genuine adopts** (Slang, Tracy), plus one cheap **upgrade** (zstd alongside lz4). The single time-sensitive decision is Slang vs. dxc+spirv-cross, because it must be made *before* the RHI pilot mass-ports shaders.

## 2. Adopt Now (P1) + one cheap P2

### ① Slang — replace the dxc + spirv-cross shader chain — **P1, verdict: upgrade**

**What.** Slang is an HLSL-superset shading language + compiler that takes one source set and emits SPIR-V, DXIL, GLSL, MSL, WGSL, with a first-class reflection API (`slangc -reflection-json` or host C++). It subsumes both dxc (compile) *and* spirv-cross (reflect + cross-compile-to-GLSL) in one tool, and adds modules + typed generics for shared shader code.

**Why THIS engine.** Spec 014 Group F has *decided* the dxc→SPIR-V + spirv-cross-`--reflect` two-tool chain for the whole RHI migration, but only the 2-shader GPU-P04 pilot exists (`test/CMakeLists.txt:509–572`). Slang collapses that into one tool that both compiles (SPIR-V for Vulkan, DXIL for DX12, GLSL for Diligent's GL backend — covering FR-F.2/F.3) and reflects, and its modules/generics directly serve the imminent "port every pass" work (shared lighting/atmosphere/noise as importable modules instead of `#include` text). **The decision window is now** — adopting after the full GLSL→HLSL port means re-tooling every pass.

**Integration steps (incremental — bank the tooling win first):**
1. Keep authoring HLSL (Slang compiles it). `find_program(LUMINUMBRA_SLANGC slangc HINTS $ENV{VULKAN_SDK}/Bin)` — already present, no FetchContent.
2. Replace the two `add_custom_command` steps (dxc compile + spirv-cross `--reflect`) with one `slangc` invocation (compile + `-reflection-json`).
3. Add a Slang-reflection-JSON variant of `ReflectSpirvReflectionJson` in `ShaderReflectionSpirv.cpp` (its parser is written to spirv-cross's `separate_images/ubos/ssbos` schema — the one real code change; small).
4. Diligent consumes the emitted SPIR-V/DXIL via `SHADER_SOURCE_LANGUAGE_BYTECODE` — **no native Slang support in Diligent is needed** (its enum has no `_SLANG` value; that's fine, Slang is an offline build tool exactly like dxc today).
5. Amend spec 014 FR-F.2/F.3 to name Slang; record the decision in the pilot commit. Later, adopt Slang modules/generics as passes are ported.

**Cost / risk.** LOW for the offline swap. mingw linkage is **irrelevant** — `slangc` is a standalone `add_custom_command` build tool, identical model to the current dxc call; no `libslang` linking into a GCC target. **Determinism: zero risk** — shader output never feeds `world_hash` (render mesh bytes excluded; sim is integer lockstep), and Slang emits deterministic explicit binding locations. One caveat: use **SPIR-V 1.3+** (Slang's 1.0–1.2 emission is experimental; the RTX/Vulkan target supports 1.3+ trivially).

### ② Tracy Profiler v0.13.1 — the standout missing tool — **P1, verdict: adopt**

**What.** A frame profiler (BSD-3) with CPU zones, frame markers, lock/memory profiling, plots, and — critically — a **GPU-zone abstraction that spans OpenGL AND Vulkan/D3D12**.

**Why THIS engine.** There is no unified profiler today (zero `ZoneScoped`/`FrameMark` in `src/`); perf tooling is bespoke and GL-specific — `GpuTimerPass` via `glBeginQuery(GL_TIME_ELAPSED)` (`RenderPipeline.cpp:1844`), `NvmlSampler`, `--render-benchmark`, SLOWFRAME. **The GL-only `GpuTimerPass` will not port to Vulkan.** Tracy is the one profiler that survives the Diligent migration and consolidates the instrumentation the team keeps hand-rolling, directly serving the determinism-critical 30 Hz tick-budget and streaming-amortization work.

**Integration steps.** FetchContent-pin to `v0.13.1` (matches the vendor pattern); link `TracyClient`; define `TRACY_ENABLE` **only** in a dedicated profiling build config; annotate the tick + render passes with `ZoneScoped`/`FrameMark` and GPU zones.

**Cost / risk.** LOW–MEDIUM. Builds under ucrt64 GCC 15 (historical MinGW friction resolved in current releases; define `TRACY_IMPORTS` if built as a shared lib; the server opens a dev-only TCP port). **Determinism: zero risk by construction** — with `TRACY_ENABLE` off, every macro expands to nothing, so gate/release binaries and `world_hash` are byte-identical. Never enable it in a gate build.

### ③ zstd alongside lz4 — cheap, do-it-now — **P2, verdict: adopt**

**What / why.** The brief's "no compression lib" is stale — **lz4 1.10.0 is already in production** compressing every chunk/far-LOD record in `WorldSaveService.cpp`. This is an *upgrade*, not a greenfield add: keep lz4 on the hot per-tick dirty-chunk save path; adopt **zstd (L6–9) for cold/high-ratio surfaces** — far-LOD tiles, full-world export/backup, asset packs — where ~2× better ratio costs nothing at read time (zstd decode >1 GB/s). For the 20–32-player wire (spec 019), first move is lz4 on snapshot deltas at zero dependency cost; the higher-ratio upgrade is **dict-zstd with a static schema-trained dictionary** (small, repetitive packets are where dict compression wins most).

**Integration steps.** `libzstd.a` + `zstd.h` are **already on the ucrt64 toolchain** — mirror the lz4 pattern: add `zstd` to `target_link_libraries` in `src/luminumbra_common/CMakeLists.txt`, `#include <zstd.h>`. The record header already carries a flags byte; add a **1-byte codec id** so lz4 and zstd records coexist and old saves stay readable. Then FetchContent-pin both lz4 and zstd to close the current unpinned-system-package reproducibility gap.

**Cost / risk.** LOW to start; LOW–MEDIUM to pin properly. **Determinism: non-issue** — `world_hash` is over the in-memory *decompressed* snapshot and lockstep hashes sim state, never compressed bytes, so the codec needs only a correct lossless round-trip. GPU decompression (GDeflate/DirectStorage) is real for the Blackwell target but D3D12-only and gated behind the RHI reaching DX12 — **defer**. Oodle — commercial license, **skip**.

## 4. Skip / Already-Covered / Decline (affirming the current stack)

- **RHI — Diligent v2.5.6 (keep, correct pick).** On the latest release; covers cross-backend HW-RT (ray queries/inline-RT), mesh shaders, HLSL single-source, async compute — exactly what specs 014/021 consume. Decisive: it is the **only credible modern RHI with a first-class OpenGL backend**, which is load-bearing for the ship-continuously raw-GL → GL-via-Diligent → per-pass Vulkan/DX12 migration with FLIP parity at each step. nvrhi (the strongest challenger) has **no GL backend** → would force a big-bang cutover, unacceptable here. Only actions: consider a version-bump toward the RT/DX12 phase; mine nvrhi's Donut/RTXDI samples as an integration *reference*, not a replacement.
- **Networking — GameNetworkingSockets (keep; already the right pick, wired right).** Shipping = `ISteamNetworkingSockets` (free SDR relay/NAT/encryption); dev = standalone GNS + Tcp/Loopback. Highest-value gap: `SteamNetworkingTransport` is **direct-IP only** — wire `ConnectP2P` + `SteamNetworkingIdentity`/lobby to unlock SDR relay, NAT punch, IP hiding (GNS-native, no new lib). Hygiene: pin `GIT_TAG v1.6.0` instead of `master`. libyojimbo/EOS correctly not adopted.
- **Model import — cgltf 1.15 (keep).** Already the sole importer, latest version, in the **offline** `asset_processor` only — never touches the lockstep path. ASSIMP would be a strict downgrade (large multi-format dep for formats this procedural engine never loads). No FBX/OBJ need in-tree.
- **ECS — EnTT (keep; decline flecs).** Determinism is enforced in *game code* — 30+ sites sort a view by `entt::to_integral(entity)` before iterating — so flecs's relationships/queries buy **zero** on the binding constraint while imposing a 340-site rewrite + re-validation of every `world_hash` gate. Do the trivial **v3.15.0 → v3.16.0** bump. (Flecs relationships map elegantly onto the emergent-ecology direction, but no filed bottleneck justifies the reopen.)
- **Serialization — keep JSON + hand-rolled binary (skip flatbuffers).** The pitch inverts here: the three proposed paths are the engine's *worst* candidates. `world_hash` is `fnv1a_64` over canonical stable-key JSON — and protobuf ("not canonical"), Cap'n Proto (not deterministic by default), and FlatBuffers (byte output depends on `flatc` vtable-dedup/default-elision) would each be a **permanent re-pinning tax** the moment the compiler updates, for zero gain over stable JSON. FlatBuffers is also ~3× bulkier than protobuf (wrong tool for the delta wire). Only defensible niche: the **tool-produced asset pipeline** (render bytes excluded from the hash) — a P3 nicety with no current pain.
- **Animation — keep the native deterministic runtime (defer ozz).** The core ozz value (clip sampling, blending, GPU-skinning palette, glTF pipeline) is **already built, tested, GPU-wired, and driving live creatures** — and deliberately deterministic (`-ffp-contract=off` + G1 checksum gate) in a way C++ ozz is *not* (its own Rust fork exists precisely because SSE vs FPU paths diverge). Real gaps (IK, blend-tree/state-machine, additive/masked, root motion, SoA-SIMD) have no live consumer until ecology ranks 81-84. When needed, implement them **natively** using ozz as the algorithmic reference — note the honest cost: ozz IK uses `atan2/sin/cos`, and libm transcendentals are **not** cross-platform deterministic, so deterministic polynomial approximations are the load-bearing work. Do **not** link ozz into the sim.
- **Text rendering — keep RmlUi + freetype (defer msdf; skip harfbuzz).** No gap: RmlUi re-rasterizes glyphs at displayed pixel size, so every shipped screen is crisp; **no in-world/3D text exists or is roadmapped**. MSDF is purely conditional on a future world-space label feature — and even then, try freetype's built-in `FT_RENDER_MODE_SDF` first (zero new deps) before msdf-atlas-gen. harfbuzz is unneeded (Latin-only; RmlUi ships a HarfBuzz sample if it ever localizes). Trivial worthwhile bump: RmlUi 6.1 → 6.2.
- **Windowing / input — keep GLFW 3.4 (defer SDL3).** GLFW owns the GL context the Diligent backend attaches to; `InputActions` persists GLFW key codes; `glfwGetTime()` is a parity-critical replay time source (~55 files). A full SDL3 swap is high-risk **mid-RHI-migration** for one real benefit (controllers) that doesn't require it: basic gamepad = GLFW 3.4's own `glfwGetGamepadState` (zero new dep); rich haptics/Steam Deck = SDL3 as a controller-*only* subsystem or the Steam Input API, GLFW keeping the window. Revisit only on a committed Steam Deck / Wayland target.
- **DirectStorage + GDeflate, C++ hot-reload, OpenUSD (skip).** DirectStorage GPU-decompress is D3D12-Windows-only (Diligent build is GL+Vk, toolchain is mingw) — HIGH/impractical; CPU-side zstd is the pragmatic streaming win. Live++ is MSVC-only, jet-live is ELF/Mach-O — full C++ hot-reload is impractical on ucrt64, and rollback-safe **shader** hot-reload already covers the high-churn loop. OpenUSD misfits a procedural-first engine. (RenderDoc in-app API already vendored — keep.)

## 5. How This Informs the In-Flight RHI Pilot (rank 66)

Two of this report's picks land squarely on the pilot, and one is time-sensitive:

1. **Decide Slang vs. dxc+spirv-cross NOW, at the pilot boundary.** Spec 014 Group F has *decided* the two-tool chain but only the 2-shader pilot is built — this is the cheapest possible moment to switch, and the last one before the full GLSL→HLSL port makes it a per-pass re-tooling job. **Recommendation: adopt Slang incrementally.** Keep authoring HLSL; swap `slangc` in for dxc+spirv-cross to bank the one-tool + host-queryable-reflection win; update `ShaderReflectionSpirv.cpp`'s JSON parser to Slang's `-reflection-json` schema; target **SPIR-V 1.3+**; feed Diligent via `SHADER_SOURCE_LANGUAGE_BYTECODE` (no native Slang support required). Then adopt Slang modules/generics as passes port (shared lighting/atmosphere/noise as importable modules). **Amend spec 014 FR-F.2/F.3 to name Slang and record the decision in the pilot commit.** Determinism is untouched (shader bytes never feed `world_hash`).

2. **Bring in Tracy as the pilot's profiler.** The bespoke `GpuTimerPass` (`glBeginQuery`) is GL-only and **will not survive the migration to Vulkan**. Tracy's GL+Vulkan GPU-zone abstraction is the one profiler that spans both backends and lets FLIP/perf parity be measured consistently as passes cut over — instrument it behind `TRACY_ENABLE` (off in gate builds) alongside the pilot work.

3. **Diligent itself needs no change** — the pilot's hard part (headless GL+Vk device creation under ucrt64 GCC 15 on the RTX 5070 Ti) is already paid, captured in `cmake/diligent.cmake`. Consider a version-bump toward the RT/DX12 phase and crib nvrhi's Donut/RTXDI HW-RT + Streamline patterns as reference.

The alternative micro-action (v3.16.0 bump) is LOW cost: one GIT_TAG edit + a clean-compile check.
