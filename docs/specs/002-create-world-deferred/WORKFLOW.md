# WORKFLOW — Create-World Deferred Items (ultracode)

How the next dev should drive spec 002 to completion. Sequential build+test+commit pipeline, one
heavyweight agent per item, each building on the prior in the main tree (the chain is linear and
builds are serial on one GPU — do NOT parallelize across worktrees). **Blocker 3a (gate honesty) is
already landed.** Read `HANDOFF.md` + `spec.md` first.

## To run
Paste the script below into the `Workflow` tool (it requires the "ultracode" opt-in). To iterate
without re-pasting, it auto-saves to the session workflows dir; re-invoke with
`Workflow({ scriptPath: "<that path>", resumeFromRunId: "<id>" })` — completed agents return cached.

## Pipeline
spike + **Item 1 (live diorama)** → Item 3b (e2e) → Item 2 (knobs) → Item 4 (constrained graph) →
integration verify. Item 1 is the centerpiece and the biggest single piece — treat it as its own
milestone (it's also the viewport Item 4 reuses).

showing a rendered 3D SLICE/DIORAMA of the candidate world, that updates IN REAL TIME as the user

a flythrough). Water reads as water, WATERFALLS show, the sky is the real atmosphere.

  set_time_of_day/set_cloud_state live. Vignette/clip the diorama edges so it reads as a model.

rebuild). Pin + green. Build luminumbra_client_app + the test target. Commit. If the full interactive
diorama is too large to finish cleanly, land the FBO render-of-candidate-world + the param/weather/tod

leave anything broken/uncompilable.`,
