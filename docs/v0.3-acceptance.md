The automated Windows acceptance drivers under `tools/gates` remain
**NEEDS-NATIVE-RUN**. `run-saved-world-lifecycle.ps1` deletes `shutdown.json`
before every session, including the two persistence phases that share their
other artifacts. A refusal passes only when its variant-specific `World open
refused:` diagnostic appears, the client exits 2 without a timeout, a fresh
`luminumbra.shutdown.v1` record has `complete: true` and `jobs_drained: true`,
and the save tree remains unchanged. Refusal qualification also requires the
verified producer manifest, its SHA-256, matching expected/before/after inventories,
and an unambiguous observed reason matching the fixed native registry. Produce
and verify the six ordered cases using [refusal_fixtures.py](https://github.com/d-addison/luminumbra/blob/devel/tools/persistence/refusal_fixtures.py)
as described in [refusal-fixtures.md](refusal-fixtures.md): `corrupt-metadata`
contains exactly `{`, and `truncated-region` removes the final payload byte of
the first region in lexical filename order. Hand-made variants do not substitute
for producer evidence; absent binding evidence remains unevaluated. The driver
checks variant-specific diagnostics, while the receipt checker binds the exact
version, parser failure or staged file path to the manifest. Unrelated or
conflicting startup errors do not qualify.

For `missing-preset`, the driver moves only the matching atlas fallback leaf into
fresh evidence, observes its absence before and after the session, and restores
its original bytes in `finally`. Use an isolated disposable package whose
ancestors cannot redirect runtime-root discovery when the default preset is
absent. See [native-refusal-evidence.md](native-refusal-evidence.md) for staging,
restoration and native evidence requirements. These refusal checks remain
separate from the pristine historical fixture copy/restore procedure below.

`check_acceptance_receipt.py` requires exactly exit code 2 for every refusal;
other nonzero codes fail, including crashes and timeout exit -1. The
`edit_roundtrip` summary requires `save_phase_schema` and `load_phase_schema`,
both exactly `luminumbra.persistence_runtime_roundtrip_phase.v1`, and matching
`save_world_hash`/`load_world_hash` strings of exactly 16 lowercase hexadecimal
characters, with a positive integer `edited_chunk_count` (booleans are invalid).
The native driver validates each artifact's schema and matching `save`/`load`
phase before producing that summary. The client emits the schema in
`src/luminumbra_client/core/scenarios/PersistenceRoundtrip.cpp`; its
`WorldSaveService::world_hash` calls `ComputeWorldStreamingStateHash`, whose
`Checksum` formatter in `src/luminumbra_common/persistence/WorldPersistenceRoundtrip.cpp`
zero-pads a 64-bit value to 16 lowercase hex characters. Save-tree and capture
SHA-256 fields retain their separate 64-character format.

The switch sequence requires at least six entries by default, at least two
distinct nonempty world IDs, and consecutive entries with different IDs.
The driver alternates the created primary world and fixture world; the minimum
counts entries, including the first load. `-SwitchCount` accepts 2 through 1000
(default 6), and the driver passes that same count as the checker's
`--min-switches`. Captures must match within each world.

`run-noui-load.ps1` requires exit 0 without a timeout, a complete P6 frame with
mean luma above 0.01, 1280x720 dimensions in both the PPM header and benchmark
top-level `width`/`height`, and `capture_context.world_id` exactly matching
`-WorldId`. The client reports that ID from its loaded `GameSession`; packages
without this field cannot qualify. On Windows, `Invoke-ClientSession` creates a
kill-on-close Job Object and starts the client or ctest suspended with
`CreateProcess(CREATE_SUSPENDED)`. It assigns the original process handle to the
job before `ResumeThread`, so the process cannot execute its first instruction
or spawn children before ownership is established. Descendants inherit job
membership even when an intermediate or the root exits. The launcher waits for
`JobObjectBasicAccountingInformation.ActiveProcesses` to reach zero; root exit
alone does not complete a session. On timeout it calls `TerminateJobObject` and
polls that count for at most 10 seconds. Remaining processes or failed job queries
throw a failing error; a cleaned-up timeout returns exit -1 with `timed_out: true`.
The non-inherited job handle also kills members on close if another error occurs.
Only the three redirected standard-stream handles are inherited by the root.
There are no PID lookups, descendant snapshots, or PID-based kill operations.

Windows 8+ nested jobs support hosts already inside a job. If their restrictions
prevent assignment, the launcher fails loudly, terminates the still-suspended
root through its original creation handle, and never resumes it or falls back
to an unowned launch. Non-Windows sessions retain root-only process-handle
termination and a bounded exit wait; that behavior is not used for native
qualification and does not guarantee descendant cleanup.

`check_v03_receipt.py` resolves evidence against `evidence_root`, relative to
the receipt directory (default `.`). The root must be relative and resolve,
with symlinks/junctions followed, to an existing directory within the resolved
receipt directory. Any `..` component is prohibited before resolution, splitting
on both `/` and `\`, even when the resolved root would remain contained
(for example, `tools/../docs` or `docs/..`). Absolute roots, roots escaping that
directory, file roots and missing roots are invalid input (exit 2). Every passing
section must reference an existing regular file strictly contained in that root. References
to the root itself (including `.` or a resolving alias), missing files, directories,
`..` traversal, and symlink/junction escapes fail with the offending reference
in the check detail. `run-v03-acceptance.ps1` copies the supplied perf evidence
and audio checklist into its output directory so its receipt remains contained
and portable. The existing Python receipt contract tests cover artifact
presence and containment; process teardown, refusal diagnostics and actual
saved-world captures still require native Windows verification under both
Windows PowerShell 5.1 and PowerShell 7.

A passing `net_soak` section must include a nonempty string list
`required_tests` and a string list `discovered_tests` containing every required
name (the native driver requires `NetSoak`). Missing or malformed discovery
fields and missing named tests fail. Unrun `unevaluated` sections may omit
discovery. Any supplied `skipped_tests` must be a nonnegative integer, excluding
booleans; positive counts fail as unexpected skips.

### Native verification: NEEDS-NATIVE-RUN

No Windows process execution is claimed by this change. Use an isolated local
evidence folder and an already built package. On Windows 8+ run the Pester-free
synthetic process harness in clean instances of both supported shells, retaining
the shell versions, exit codes and output:

```powershell
powershell.exe -NoProfile -File tools/gates/test-acceptance-process-ownership.ps1
pwsh.exe -NoProfile -File tools/gates/test-acceptance-process-ownership.ps1
```

The harness uses Python processes, redirects both streams, checks quoting and
normal exit 7, then requires timeout exit -1 for each of these trees:

- Immediate child: spawn at the root's first application instructions, testing
  assignment before execution.
- Exited intermediate: root stays alive, intermediate spawns a worker and exits
  before timeout; the orphan worker must stop.
- Late children: repeatedly spawn near the deadline; children created during
  cleanup must stop without another ancestry snapshot.
- Parent-exit race: root exits 0 immediately after spawning a long-lived worker;
  the session must continue tracking the worker and eventually time out.
- Late parent exit: root spawns after a delay and exits near the deadline; the
  worker must still be contained and terminated.

A returned timeout proves the job query reached zero active processes after
termination. The harness additionally checks that descendant heartbeat files
stop growing and an unrelated process retained by handle continues progressing.
It shadows CIM with a throwing function to check that unavailable enumeration
cannot affect cleanup. PID reuse cannot redirect termination because no process
is reopened by ID. Synthetic workers have a finite lifetime even if an assertion
fails; the harness removes its temporary folder and cleans up its sentinel.

Repeat the harness inside the native runner's enclosing job to exercise nested
assignment. For the failure case, use a runner whose enclosing job denies nested
assignment: require an `AssignProcessToJobObject failed` diagnostic and no
fixture `.started` marker (the suspended root must never execute). Treat any
cleanup-query error or nonzero active count after the bounded wait as a failed
native run. Finally run the actual client and ctest acceptance drivers, checking
normal exits and intentionally forced timeouts, and retain their receipts and
fresh shutdown/capture artifacts. Native refusal diagnostics, junction
containment and saved-world capture checks remain required separately.

```powershell
$runtimeRoot = 'C:\luminumbra\candidate'

if ($LASTEXITCODE -ne 0) { throw 'catalog session failed' }
```

## Native client hang (PID 66604)

The private `2871c72` session that ended with exit `0xCFFFFFFF` was a Windows
Application Hang (Application log event 1002, "stopped interacting with Windows
and was closed", with a WER AppHangB1 report), closed manually by the operator;
it was not a crash: no exception filter ran, no minidump or shutdown record was
written, both log sinks stopped at 21:47:33 and the quit/shutdown save rewrote
`world_info.json` at 21:47:47. Four earlier audio-enabled sessions with the same
per-frame log traffic had exited cleanly; the failing session alone had
process-loopback audio recorders attached.

Two changes follow. The audio spatial-clustering binding logged one INFO line per
rendered frame on the render thread (77,659 lines in that session); it now logs
only when the bound physics system changes, with a device-free regression. An
opt-in `--hang-watchdog-seconds N` watchdog polls a main-loop heartbeat and, when
it stalls, writes `hang-<ts>.txt` into the crash directory with raw file calls and
asks an external process (`rundll32 comsvcs.dll,MiniDump`) for a minidump beside
it. The specific hazard removed is suspension of a thread that may hold the
allocator or logger lock: the report path allocates nothing after arm time,
never logs, never enters the debug-help library, and waits on the helper for at
most 30 s (cancelled at shutdown, with the helper left to finish on its own).
It still depends on the operating system launching the helper and on the crash
directory being prepared at arm time. The capture is best-effort and
Windows-only, the dump is symbolized offline with the retained PDB, the
heartbeat is polled every 250 ms, and the threshold must exceed the longest
legitimate stage (such as a large save). The shutdown record covers the
milestones from the quit save to job-system shutdown; the `complete` field is
an additive change to the record. With
the watchdog armed, `shutdown.json` is rewritten after every teardown milestone
so a teardown hang localizes to its last stage; with it off, the record is
written once at the end as before.

An instrumented reproduction matrix on the same package did not reproduce the
hang: cells with the fixed build and six recorders, with a capture still
attached at quit, with the exact original binary and its per-frame log, and
with that binary's stdout redirected over the WSL network redirector
(133,283 lines) all exited 0 with all eleven shutdown milestones. The owner
accepted closure on that basis: the incident is recorded as not reproducible
after the fix, every remaining native acceptance run launches with the
watchdog armed and stdout on local disk, and a recurrence must be examined
through its actual hang report and dump before any verdict; a recurrence
blocks publication.

verification code. Its version-only namespace also collided between artifact
profiles. The corrected generator inventories the exact source archive, retains
SHA-256 alongside SHA-1, records the reproducible creation convention, and derives
a unique document identity from its complete content. The source workflow checks
the pinned official schema, inventory semantics and exact archive membership and
digests before attestation. Ordinary engine tests use the standard library and
isolated Git fixtures; schema dependencies belong to release tooling. This is a
file inventory, not a complete dependency or license audit. See

## Remaining release gates and limits

At the user's direction, audio playback is disabled for v0.3 and its private
preview. Normal client startup uses the null backend regardless of persisted
volume, and disabled settings report that state. `--enable-audio` is an explicit
experimental diagnostic opt-in; `--no-audio` always suppresses it. Existing audio
code and private evidence remain available for a separate redesign workstream.
Release acceptance verifies silent startup and truthful controls; it does not
claim acceptable sound design or complete audible-event coverage.

Final committed-candidate checks, applicable native/manual coverage, the unchanged
120-second UCRT64 guard, server-load qualification, paired performance gates,
independent Astra/xhigh verification, strict CI promotion, signed source-only
publication and independent release-download verification remain required.

Finite surface residency, the 3,200 m far plane, finite cave residency and omitted
distant caves/edits remain visible limitations. Cave captures still expose the
finite cave boundary. Audio audibility/event coverage, broader hardware and real
GNS/Steam transport qualification must not be inferred from decoding, software GL
or compile probes. The original intermittent server-load crash retains its own
reproduction and unresolved cause; the separate MSVC exception-configuration fix
does not establish its cause.

See the [roadmap](roadmap.md) and its individual acceptance issues for ownership,
dependencies and closure requirements. Engine/game extraction follows verified
publication and the agreed roadmap approval.
