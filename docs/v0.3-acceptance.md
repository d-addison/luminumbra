This record separates historical evidence from current release preparation. v0.3.0 is
not yet published. Earlier executables and packages do not qualify the current
candidate.

## Saved worlds

Native saved-world packets remain **NEEDS-NATIVE-RUN**. Broader matrix completion is
planned for v0.3.1; the owner Windows smoke above remains required for v0.3.0.

The catalog now performs complete validation on one background worker, coalesces
refreshes into one pending request, cancels obsolete work and publishes results
only on the UI thread. The selector displays a pending state and disables loading
until validation completes. World opening still validates again before replacing
the current world; supported formats and corruption checks are unchanged.

The automated Windows acceptance drivers under `tools/gates` remain
**NEEDS-NATIVE-RUN**. `run-saved-world-lifecycle.ps1` deletes `shutdown.json`
before every session, including the two persistence phases that share their
other artifacts. A refusal passes only when its variant-specific `World open
refused:` diagnostic appears, the client exits 2 without a timeout, a fresh
`luminumbra.shutdown.v1` record has `complete: true` and `jobs_drained: true`,
and the save tree remains unchanged. Refusal qualification also requires the
verified producer manifest, its SHA-256, matching expected/before/after inventories,
and an unambiguous observed reason matching the fixed native registry. Produce
and verify the six ordered cases using
[refusal_fixtures.py](https://github.com/d-addison/luminumbra/blob/devel/tools/persistence/refusal_fixtures.py)
as described in [refusal-fixtures.md](refusal-fixtures.md): `corrupt-metadata`
contains exactly `{`, and `truncated-region` removes the final payload byte of
the first region in lexical filename order. Hand-made variants do not substitute
for producer evidence; absent binding evidence remains unevaluated. The driver
checks variant-specific diagnostics, while the receipt checker binds the exact
version, parser failure or staged file path to the manifest. Unrelated or
conflicting startup errors do not qualify.

For `missing-preset`, the driver moves only the matching atlas fallback leaf into
fresh evidence, observes its absence before and after the session, and restores
its original bytes in `finally`. Use an isolated disposable package whose
ancestors cannot redirect runtime-root discovery when the default preset is
absent. See [native-refusal-evidence.md](native-refusal-evidence.md) for staging,
restoration and native evidence requirements. These refusal checks remain
separate from the pristine historical fixture copy/restore procedure below.

`check_acceptance_receipt.py` records `required_refusal_variants` and
`selected_refusal_variants` in every verdict. A `--refusal-variants` selection
omitting any required case has `scope: "subset"`, including a passing selection;
complete matrix qualification requires `scope: "full"` and a passing verdict.
The checker requires exactly exit code 2 for every refusal;
other nonzero codes fail, including crashes and timeout exit -1. The
`edit_roundtrip` summary requires `save_phase_schema` and `load_phase_schema`,
both exactly `luminumbra.persistence_runtime_roundtrip_phase.v1`, and matching
`save_world_hash`/`load_world_hash` strings of exactly 16 lowercase hexadecimal
characters, with a positive integer `edited_chunk_count` (booleans are invalid).
The native driver validates each artifact's schema and matching `save`/`load`
phase before producing that summary. Only absent phase artifacts are missing
evidence; existing artifacts with invalid JSON, schema or phase fail the driver,
even if the other phase is absent. The client emits the schema in
`src/luminumbra_client/core/scenarios/PersistenceRoundtrip.cpp`; its
`WorldSaveService::world_hash` calls `ComputeWorldStreamingStateHash`, whose
`Checksum` formatter in `src/luminumbra_common/persistence/WorldPersistenceRoundtrip.cpp`
zero-pads a 64-bit value to 16 lowercase hex characters. Save-tree and capture
SHA-256 fields retain their separate 64-character format.

The switch sequence requires at least six entries by default, indices in recorded
order from 1 through the entry count, and two distinct nonempty world IDs
alternating throughout. The driver loads the fixture world first, then the newly
created primary world. The minimum counts entries, including the first load.
`-SwitchCount` accepts 2 through 1000
(default 6), and the driver passes that same count as the checker's
`--min-switches`. Captures must match within each world.

`run-noui-load.ps1` requires exit 0 without a timeout, a complete P6 frame with
mean luma above 0.01, 1280x720 dimensions in both the PPM header and benchmark
top-level `width`/`height`, and `capture_context.world_id` exactly matching
`-WorldId`. The client reports that ID from its loaded `GameSession`; packages
without this field cannot qualify. On Windows, `Invoke-ClientSession` creates a
kill-on-close Job Object and starts the client or ctest suspended with
`CreateProcess(CREATE_SUSPENDED)`. It assigns the original process handle to the
job before `ResumeThread`, so the process cannot execute its first instruction
or spawn children before ownership is established. Descendants inherit job
membership even when an intermediate or the root exits. The launcher waits for
`JobObjectBasicAccountingInformation.ActiveProcesses` to reach zero; root exit
alone does not complete a session. On timeout it calls `TerminateJobObject` and
polls that count for at most 10 seconds. Remaining processes or failed job queries
throw a failing error; a cleaned-up timeout returns exit -1 with `timed_out: true`.
The non-inherited job handle also kills members on close if another error occurs.
Only the three redirected standard-stream handles are inherited by the root.
There are no PID lookups, descendant snapshots, or PID-based kill operations.

Windows 8+ nested jobs support hosts already inside a job. If their restrictions
prevent assignment, the launcher fails loudly, terminates the still-suspended
root through its original creation handle, and never resumes it or falls back
to an unowned launch. Non-Windows sessions retain root-only process-handle
termination and a bounded exit wait; that behavior is not used for native
qualification and does not guarantee descendant cleanup.

`check_v03_receipt.py` resolves evidence against `evidence_root`, relative to
the receipt directory (default `.`). The root must be relative and resolve,
with symlinks/junctions followed, to an existing directory within the resolved
receipt directory. Any `..` component is prohibited before resolution, splitting
on both `/` and `\`, even when the resolved root would remain contained
(for example, `tools/../docs` or `docs/..`). Absolute roots, roots escaping that
directory, file roots and missing roots are invalid input (exit 2). Every passing
section must reference an existing regular file strictly contained in that root. References
to the root itself (including `.` or a resolving alias), missing files, directories,
`..` traversal, and symlink/junction escapes fail with the offending reference
in the check detail. `run-v03-acceptance.ps1` copies the supplied perf evidence
and audio checklist into its output directory so its receipt remains contained
and portable. The orchestrator requires an empty or absent output
directory before running any section and preserves existing evidence on refusal.
When `run-render-qualification.ps1` is absent, the orchestrator records
`render_qualification` as `unevaluated`, with no evidence and an explicit reference
to [issue #241](https://github.com/d-addison/luminumbra/issues/241). That driver
belongs to the render-qualification tooling stack deferred to v0.3.1. The dry-run
output reports this deferral too. With all other sections passing, the overall
verdict is `unevaluated` (exit 3); any failing section still makes it `fail`
(exit 1). The verdict retains the deferral reason, so outstanding render
qualification cannot count as a pass. When the driver exists, the orchestrator
runs and evaluates it as before; `-SkipRender` also remains unevaluated.
For v0.3.0, native render rows remain **NEEDS-NATIVE-RUN** and are captured cell
by cell with existing devel tooling. Tooling deferral does not qualify those rows.

A passing `net_soak` section must record `skipped_tests` as the integer 0.
The lifecycle driver records save-directory names before `create_edit_save` and
requires exactly one new directory afterwards to identify the primary world.
The existing Python receipt contract tests cover artifact
presence and containment; process teardown, refusal diagnostics and actual
saved-world captures still require native Windows verification under both
Windows PowerShell 5.1 and PowerShell 7.

A passing `net_soak` section must include a nonempty string list
`required_tests` and a string list `discovered_tests` containing every required
name (the native driver requires `NetSoak`). Missing or malformed discovery
fields and missing named tests fail. Unrun `unevaluated` sections may omit
discovery. Any supplied `skipped_tests` must be a nonnegative integer, excluding
booleans; positive counts fail as unexpected skips.

### Native verification: NEEDS-NATIVE-RUN

No Windows process execution is claimed by this change. Use an isolated local
evidence folder and an already built package. On Windows 8+ run the Pester-free
synthetic process harness in clean instances of both supported shells, retaining
the shell versions, exit codes and output:

```powershell
powershell.exe -NoProfile -File tools/gates/test-acceptance-process-ownership.ps1
pwsh.exe -NoProfile -File tools/gates/test-acceptance-process-ownership.ps1
```

The harness uses Python processes, redirects both streams, checks quoting and
normal exit 7, then requires timeout exit -1 for each of these trees:

- Immediate child: spawn at the root's first application instructions, testing
  assignment before execution.
- Exited intermediate: root stays alive, intermediate spawns a worker and exits
  before timeout; the orphan worker must stop.
- Late children: repeatedly spawn near the deadline; children created during
  cleanup must stop without another ancestry snapshot.
- Parent-exit race: root exits 0 immediately after spawning a long-lived worker;
  the session must continue tracking the worker and eventually time out.
- Late parent exit: root spawns after a delay and exits near the deadline; the
  worker must still be contained and terminated.

A returned timeout proves the job query reached zero active processes after
termination. The harness additionally checks that descendant heartbeat files
stop growing and an unrelated process retained by handle continues progressing.
It shadows CIM with a throwing function to check that unavailable enumeration
cannot affect cleanup. PID reuse cannot redirect termination because no process
is reopened by ID. Synthetic workers have a finite lifetime even if an assertion
fails; the harness removes its temporary folder and cleans up its sentinel.

Repeat the harness inside the native runner's enclosing job to exercise nested
assignment. For the failure case, use a runner whose enclosing job denies nested
assignment: require an `AssignProcessToJobObject failed` diagnostic and no
fixture `.started` marker (the suspended root must never execute). Treat any
cleanup-query error or nonzero active count after the bounded wait as a failed
native run. Finally run the actual client and ctest acceptance drivers, checking
normal exits and intentionally forced timeouts, and retain their receipts and
fresh shutdown/capture artifacts. Native refusal diagnostics, junction
containment and saved-world capture checks remain required separately.

### Player position and rendering policy

Both local-player collision shapes use a common feet origin. Lower-sphere slope
contacts support walking, and standing clearance is checked at the standing
shape's center of mass. Shape changes use Jolt's penetration slop; the client
updates its stance only when the change is accepted.

The terrain regression compares feet against real collider rays at the player's
current x/z at both 1/60 s and the 50 ms frame clamp. Additional regressions cover
repeated stance changes, low-ceiling refusal and recovery, walking on a 45-degree
slope, and grounded state during collision bootstrap. These checks do not assert
stationary idle motion; grounded velocity includes a downward component.

The spawn anchor is the standing eye position over the controller's feet
regardless of stance (`player/SaveAnchor.h`). Both pause-menu quit and shutdown
save this anchor; world entry subtracts the standing eye height to recover feet.
The header-only regression in `test/client/client_policy_test.cpp` covers standing
and crouched saves. The render pipeline and world-entry gate use the same
`LUMIN_TREE_IMPOSTORS` predicate (`rendering/TreeImpostorPolicy.h`), with regression
coverage for the documented disable values.

Packaged entry, stance, noclip return and saved-world switching remain
**NEEDS-NATIVE-RUN**.

### Synthetic historical profile: NEEDS-NATIVE-RUN

Outstanding historical-profile native evidence is deferred to v0.3.1; this procedure records no pass.

The synthetic fixture's historical profile writes 5,433 noise chunks with seed
1337. Its coordinate-uniqueness test does not qualify a save at that scale.
Historical CLI generation, receipt verification, and load/catalog qualification
remain **NEEDS-NATIVE-RUN**.
The writer accepts 1 through 65,536 chunks: just over twelve times the largest
real profile (5,433), allowing explicit headroom while bounding allocations.
The fixture library and CLI are available only with `BUILD_TESTING=ON`.

A native Windows operator uses an already built candidate with its runtime assets
installed. Set the paths below to that candidate and this checkout. Use a fresh
`ac5a_historical` world ID (the writer refuses existing leaves), and store evidence
outside the save tree. Run these exact PowerShell commands, checking each exit
code before continuing:

```powershell
$runtimeRoot = 'C:\luminumbra\candidate'
$engineSource = 'C:\luminumbra\engine'
$fixtureExe = Join-Path $runtimeRoot 'bin\luminumbra_save_fixture.exe'
$clientExe = Join-Path $runtimeRoot 'bin\luminumbra_client_app.exe'
$receiptTool = Join-Path $engineSource 'tools\persistence\save_receipt.py'
$saveDir = Join-Path $runtimeRoot 'worlds\saves\ac5a_historical'
$receipt = Join-Path $runtimeRoot 'ac5a-historical-receipt.json'
Set-Location $runtimeRoot
& $fixtureExe --out $runtimeRoot --profile historical --world-id ac5a_historical --preset (Join-Path $runtimeRoot 'worlds\atlas\presets\default.json') > ac5a-fixture-report.json
if ($LASTEXITCODE -ne 0) { throw 'historical fixture generation failed' }
python $receiptTool snapshot $saveDir --out $receipt
if ($LASTEXITCODE -ne 0) { throw 'receipt snapshot failed' }
python $receiptTool verify $saveDir $receipt
if ($LASTEXITCODE -ne 0) { throw 'receipt verification failed' }
$pristine = Join-Path $runtimeRoot 'ac5a-historical-pristine'
if (Test-Path $pristine) { throw 'pristine copy path already exists' }
Copy-Item -Recurse $saveDir $pristine
& $clientExe --load-world ac5a_historical --no-menu-backdrop
if ($LASTEXITCODE -ne 0) { throw 'direct world load failed' }
Remove-Item -Recurse -Force $saveDir
Copy-Item -Recurse $pristine $saveDir
python $receiptTool verify $saveDir $receipt
if ($LASTEXITCODE -ne 0) { throw 'pristine fixture restore failed' }
& $clientExe --no-menu-backdrop
if ($LASTEXITCODE -ne 0) { throw 'catalog session failed' }
```

The two client commands are interactive: after direct loading, record the log's
`World state loaded: 5433 chunks adopted (5433 in snapshot)` line for this save
path, then close cleanly. In the second session, open the saved world selector,
wait for validation, confirm `Synthetic Fixture` is available, select that world,
and record the same adoption diagnostic before closing cleanly. A clean client exit
always saves the open world (`SaveWorldState()` and `SaveWorld()` on shutdown), so
the save tree is expected to change after each session; the receipt therefore
qualifies the fixture before each session, restored from the pristine copy, not the
tree after shutdown. Adoption and catalog success are established by the recorded
diagnostics, not by an unchanged receipt. Retain the fixture JSON report (`chunks`
must be 5433), receipt, verification output, client logs, catalog screenshot, and
exit codes. An exit code alone does not establish the requested world loaded or
that catalog validation succeeded.

## Hang diagnostics

Audio spatial-clustering bindings log when the bound physics system changes,
with a device-free regression. The opt-in `--hang-watchdog-seconds N` watchdog
polls a main-loop heartbeat every 250 ms. On a stall it writes `hang-<ts>.txt` into
the crash directory using raw file calls and asks an external process
(`rundll32 comsvcs.dll,MiniDump`) for a minidump beside it.

The report path allocates nothing after arm time, never logs and never enters
the debug-help library. It waits for the helper for at most 30 seconds; shutdown
cancels that wait and leaves the helper to finish. Capture is best-effort and
Windows-only: it depends on the operating system launching the helper and on
the crash directory being prepared at arm time. The threshold must exceed the
longest legitimate stage, such as a large save. Dumps require the matching PDB
for offline symbolization.

The shutdown record covers milestones from the quit save to job-system shutdown.
With the watchdog armed, `shutdown.json` is rewritten after every teardown
milestone; otherwise it is written once at the end. The watchdog regressions cover
an unstarted loop, stalled and advancing heartbeats, rearming, handler exceptions
and polling-thread shutdown. Packaged hang capture and teardown qualification
remain **NEEDS-NATIVE-RUN**.

## Rendering and determinism regression coverage

- Water readback covers caustic normalization and narrow shoreline foam.
- Soil ambient reflection uses a 64x64 RG16F GGX/Schlick lookup (16 KiB).
  `python3 tools/rendering/generate_environment_brdf.py --check` reproduces it.
- Foliage/weather readback covers opaque and soft-edge pixels. Rays compose
  before grass; weather and aerial effects apply to the blended scene. Grass
  alpha occludes rays against cleared sky depth. Weather/fog use background
  G-buffer depth and normals for grass, an approximation at silhouettes.
- Grass and terrain use the same projected cloud field and five shadow taps.
- The active glass pass borrows shared depth as a renderbuffer. Resize,
  render-scale changes and cleanup release OIT before that borrowed depth.
  Regressions cover visible and occluded panes at recreated framebuffer sizes,
  and refraction against a nonuniform background at half and quarter scale.
- MSVC AVX2 Simplex 2D preserves the established skew/unskew operation order.
  Existing terrain height and topology pins define the expected samples; see
  [terrain determinism](msvc-terrain-determinism.md).

These regressions do not qualify whole-scene appearance, hardware performance,
resource residency or a final release package. Native ground, high-altitude,
cave-air and forest captures remain **NEEDS-NATIVE-RUN**, with package identity,
poses, warmup, sample counts and workload recorded in their evidence.

## Source-release inventory

The SPDX 2.3 generator inventories the exact source archive, records the creation
timestamp and reproducible creation convention, includes SHA-256 and required
SHA-1 file digests and the analyzed-package verification code, and derives a
unique document identity from its complete content. The source workflow checks
the pinned official schema, inventory semantics and exact archive membership and
digests before attestation. Ordinary engine tests use the standard library and
isolated Git fixtures; schema dependencies belong to release tooling. This is a
file inventory, not a complete dependency or license audit. See
[release tooling](https://github.com/d-addison/luminumbra/blob/devel/tools/release/README.md) and
[issue #119](https://github.com/d-addison/luminumbra/issues/119).

truthful controls; audible-event coverage remains a separate qualification.
